Riktig typografi på `<label>`, og en fast måte å markere påkrevde og valgfrie felt på. Setter du opp et helt felt, er [Field](../field/) som regel enklere. Den setter `for`, `id` og `aria-describedby` for deg.

## How to use it

`lt` brukes på to måter, og hvilken avhenger av om du lager elementet eller finner det.

**Lager du markupen,** sprer du attributtene inn. Det er veien i React, Astro og alt annet som rendrer:

```tsx
import { lt } from "@lo-tek/interfaces/react"

<label {...lt.label()} htmlFor="navn">Fullt navn</label>
<input {...lt.input({ type: "text" })} id="navn" />
```

Importen går til `/react` her, siden blokka er JSX. Derfra heter nøklene `className` og `htmlFor`. I Astro og alt annet uten React importerer du `@lo-tek/interfaces` og får `class` og `for`.

**Står elementet der fra før,** setter du dem på det. Det er veien når du forbedrer HTML en server eller en mal har sendt:

```ts
import { lt } from "@lo-tek/interfaces"

const ledetekst = document.querySelector<HTMLLabelElement>("#epost-label")
if (!ledetekst) throw new Error("fant ikke elementet")

lt.setAttributes(ledetekst, lt.label({ required: "symbol" }))
ledetekst.htmlFor = "epost"
```

`for` setter du selv. Funksjonen returnerer bare LO-TEKs egne attributter.

Setter du opp et helt felt, gjør [`lt.field`](../field/) både markeringen og koblingen til kontrollen:

```ts
const input = document.querySelector<HTMLInputElement>("#epost")

const felt = lt.field({ id: "epost", required: "symbol" })

lt.setAttributes(ledetekst, felt.label)
lt.setAttributes(input, lt.input({ type: "email" }), felt.control)
if (input) input.required = true
```

`required: "symbol"` gir bare stjernen. At feltet må fylles ut, sier `required` på selve feltet.

| Attributt | Effekt |
| --- | --- |
| *(utelatt)* | Vanlig ledetekst |
| `data-required="symbol"` | ` *` i farefargen |
| `data-required="text"` | ` (påkrevd)` i farefargen |
| `data-optional=""` | ` (valgfri)` i dempet farge |
| `aria-disabled="true"` | Dempet tekstfarge |

Velg én av `data-required` og `data-optional` og hold deg til den gjennom skjemaet. Setter du begge, viser systemet bare den ene: det er det samme `::after`, og byggefunksjonen dropper `data-optional` når feltet er påkrevd.

## Sammen med et felt

`for` må matche `id` på feltet. Uten koblingen leses ikke ledeteksten opp når feltet får fokus, og et klikk på teksten flytter ikke fokus dit.

## Classes you can style

| Klasse | Hva det er |
| --- | --- |
| `.lt-label` | Ledeteksten. Markeringene legges på med `::after`. |

Markeringen bak `data-required` og `data-optional` er tekst i `::after`, og teksten leses fra en variabel. Da kan den byttes, eller oversettes, uten å endre markupen:

| Variabel | Standard |
| --- | --- |
| `--lt-label-required-symbol` | `" *"` |
| `--lt-label-required-text` | `" (påkrevd)"` |
| `--lt-label-optional-text` | `" (valgfri)"` |

```css
:root:lang(en) {
	--lt-label-required-text: " (required)";
	--lt-label-optional-text: " (optional)";
}
```

Variablene gjelder også `.lt-legend` i [Fieldset](../fieldset/). Se [Oversettelse](../../translation/).

Se [Tilpasning](../../customising/) for hvordan laget virker.

## Accessibility

- `data-required` er bare visuelt. Sett `required` på selve feltet, ellers vet ikke skjermleseren at det må fylles ut.
- Stjernen og «(påkrevd)» legges til med `::after`. Innhold i `::after` regnes med i navnet på feltet, så en skjermleser kan lese det etter ledeteksten. Det er `required` på feltet som sier at det må fylles ut.
- Skjul aldri ledeteksten helt. Trenger du den visuelt borte, bruk `.lt-sr-only` fra `sr-only.css` framfor `placeholder`, som forsvinner så snart brukeren skriver.
