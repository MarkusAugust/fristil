`fs-link` gir `<a>` den lenkestilen resten av systemet bruker, med tydelig understrek, hover og fokusmarkering. Standardfargen er `--semantic-interactive-main`.

Skal lenken se ut som en knapp — for eksempel som hovedhandlingen i et skjema — bruker du [Button](../button/) på `<a>`-elementet i stedet.

## Importer

```js
import "@fristil/designsystem/tokens.css"
import "@fristil/designsystem/link.css"
```

Uten byggesteg:

```html
<link rel="stylesheet" href="@fristil/designsystem/tokens.css" />
<link rel="stylesheet" href="@fristil/designsystem/link.css" />
```

## Lenke som ikke er klikkbar ennå

<Tabs>
  <TabItem label="Eksempel">
    <Preview stiler={["link"]}>
      <a class="fs-link" href="#">Se kvittering</a>
      <a class="fs-link" aria-disabled="true" href="#">Se årsoppgave</a>
    </Preview>
  </TabItem>
  <TabItem label="Kode">
    ```html
    <a class="fs-link" href="/kvittering">Se kvittering</a>
    <a class="fs-link" aria-disabled="true" href="/arsoppgave">Se årsoppgave</a>
    ```
  </TabItem>
</Tabs>

`aria-disabled="true"` demper fargen og slår av klikk med `pointer-events: none`. Lenken blir liggende i tabrekkefølgen, slik at en skjermleser kan lese den og fortelle at den er utilgjengelig — det er forskjellen fra å fjerne `href`.

Merk at `pointer-events: none` stopper musa, men ikke tastaturet. Er det viktig at lenken ikke kan følges i det hele tatt, må du også fjerne `href` eller stoppe klikket i JavaScript.

## Tilgjengelighet

- Lenketeksten skal gi mening lest alene. Mange skjermlesere kan liste opp alle lenker på siden, og da hjelper «Se faktura for mars» der «Klikk her» ikke sier noe.
- Ikke fjern `outline` på `:focus-visible`. Den følger med `fs-link` og er det eneste tastaturbrukere har å navigere etter.
- Åpner lenken i ny fane, si det i teksten eller med `aria-label`. Uventet fanebytte er vanskelig å oppdage for den som ikke ser skjermen.
- Er lenken deaktivert, forklar hvorfor i teksten rundt. `aria-disabled` sier at noe ikke går, ikke hva brukeren skal gjøre i stedet.
