`fs-button` er en CSS-komponent. Du får den ved å sette klassen på et vanlig `<button>`-element — ingen JavaScript lastes, og den fungerer likt i alle rammeverk.

## Importer

```js
import "@fristil/designsystem/tokens.css"
import "@fristil/designsystem/button.css"
```

Uten byggesteg:

```html
<link rel="stylesheet" href="@fristil/designsystem/tokens.css" />
<link rel="stylesheet" href="@fristil/designsystem/button.css" />
```

## Varianter

Varianten sier hvor tung handlingen er. Uten `data-variant` får du primærknappen.

<Tabs>
  <TabItem label="Eksempel">
    <Preview stiler={["button"]}>
      <button class="fs-button">Send søknad</button>
      <button class="fs-button" data-variant="secondary">Lagre utkast</button>
      <button class="fs-button" data-variant="ghost">Legg til vedlegg</button>
      <button class="fs-button" data-variant="danger">Slett søknad</button>
    </Preview>
  </TabItem>
  <TabItem label="Kode">
    ```html
    <button class="fs-button">Send søknad</button>
    <button class="fs-button" data-variant="secondary">Lagre utkast</button>
    <button class="fs-button" data-variant="ghost">Legg til vedlegg</button>
    <button class="fs-button" data-variant="danger">Slett søknad</button>
    ```
  </TabItem>
</Tabs>

| `data-variant` | Når du bruker den |
| --- | --- |
| *(utelatt)* | Hovedhandlingen på siden. Bruk bare én. |
| `secondary` | Alternativ handling ved siden av hovedhandlingen. |
| `ghost` | Lav vekt — verktøylinjer og handlinger inne i tabeller eller kort. |
| `danger` | Handlinger som sletter eller ikke kan angres. |

`disabled` finnes bare på `<button>`. Ser knappen din ut som en lenke i markupen, bruker du `aria-disabled="true"` i stedet — da beholder skjermlesere elementet i lesefokus og kan fortelle at det er utilgjengelig.

```html
<a class="fs-button" aria-disabled="true" href="/neste-steg">Gå videre</a>
```

## Lenke som ser ut som knapp

Navigerer du brukeren til et annet sted, skal elementet være en `<a>` selv om det ser ut som en knapp. Da virker høyreklikk, midtklikk og «åpne i ny fane» som forventet.

## TypeScript

Skriver du `data-variant` for hånd, er det en vanlig streng, og `"secundary"` feiler stille. Importerer du hjelperen, tar editoren skrivefeilen før du rekker å lagre.

```ts
import {
	getButtonStyleAttributes,
	type ButtonVariant,
} from "@fristil/designsystem/button"

const variant: ButtonVariant = "secondary"

getButtonStyleAttributes(variant)
// { class: "fs-button", "data-variant": "secondary" }

getButtonStyleAttributes("primary")
// { class: "fs-button" } — primær er standard og trenger ikke attributtet
```

Hjelperen returnerer bare Fristils egne attributter. Resten av elementet eier du selv:

```ts
const attributter = {
	...getButtonStyleAttributes("danger"),
	type: "submit",
	"aria-label": "Slett søknaden permanent",
}
```

Kommer varianten fra et API eller en URL, valider den før bruk:

```ts
import {
	getButtonStyleAttributes,
	isButtonVariant,
} from "@fristil/designsystem/button"

const fraServer = String(svar.variant)
const variant = isButtonVariant(fraServer) ? fraServer : "primary"

getButtonStyleAttributes(variant)
```

Se [Typesikker bruk](../../typesikker-bruk/) for det samme mønsteret på tvers av komponentene.

## Tilgjengelighet

- `<button>` utfører en handling, `<a>` flytter deg et annet sted. Velg etter hva som faktisk skjer, ikke etter hvordan det ser ut.
- Inne i et `<form>` er `type="submit"` standard i nettleseren. Skal knappen ikke sende skjemaet, må du skrive `type="button"` eksplisitt.
- La teksten beskrive handlingen: «Slett bruker» sier mer enn «OK».
- Ikke bruk en deaktivert knapp som eneste forklaring på hvorfor noe ikke går. Vis heller en feilmelding brukeren kan gjøre noe med.
