Gruppen er radioknapper i forkledning. Hvert alternativ er en `<label>` med en `<input type="radio">` inni, krympet bort visuelt. Da beholder du piltastene, `FormData` og at skjermleseren sier «2 av 3», uten at noe av det må skrives på nytt.

`lt` brukes på to måter, og hvilken avhenger av om du lager elementet eller finner det.

**Lager du markupen,** sprer du attributtene inn. Det er veien i React, Astro og alt annet som rendrer:

```tsx
import { lt } from "@lo-tek/interfaces/react"

<fieldset {...lt.toggleGroup()}>
  <legend {...lt.srOnly()}>Visning</legend>
  <label className={lt.toggleGroup.option}>
    <input type="radio" name="visning" value="liste" defaultChecked />
    Liste
  </label>
</fieldset>
```

Importen går til `/react` her, siden blokka er JSX. Derfra heter nøklene `className` og `htmlFor`. I Astro og alt annet uten React importerer du `@lo-tek/interfaces` og får `class` og `for`.

**Står elementet der fra før,** setter du dem på det. Det er veien når du forbedrer HTML en server eller en mal har sendt:

```ts
import { lt } from "@lo-tek/interfaces"

const gruppe = document.querySelector<HTMLFieldSetElement>("#visning")
if (!gruppe) throw new Error("fant ikke elementet")

lt.setAttributes(gruppe, lt.toggleGroup())
```

`lt.toggleGroup.option` gir klassen på hvert alternativ. Selve valget leser du som vanlig:

```ts
gruppe.addEventListener("change", (hendelse) => {
  const valgt = (hendelse.target as HTMLInputElement).value
})
```

`<legend>` er påkrevd selv når den er skjult. Uten den vet ikke den som hører siden hva de tre alternativene velger mellom.

## Når det ikke er denne du skal ha

| Situasjon | Komponent |
| --- | --- |
| Ett valg blant tre til fem korte alternativer | **Toggle Group** |
| Ett valg blant mange, eller lange alternativer | [Radio](../radio/) i en [Fieldset](../fieldset/) |
| Flere valg samtidig | [Checkbox](../checkbox/) |
| Av og på for én innstilling | [Switch](../switch/) |
| Handlinger, som «fet, kursiv, understreket» | Knapper med `aria-pressed` |

## Classes you can style

| Klasse | Hva det er |
| --- | --- |
| `.lt-toggle-group` | Gruppen |
| `.lt-toggle-group__option` | Ledeteksten rundt hvert alternativ |

| Variabel | Standard |
| --- | --- |
| `--lt-toggle-group-radius` | `var(--lt-spacing-1)` |
| `--lt-toggle-group-height` | `var(--lt-spacing-10)` |
| `--lt-toggle-group-padding` | `0 var(--lt-spacing-4)` |

Den valgte flaten settes med `:has(input:checked)`, altså fra tilstanden på den ekte radioknappen. Det er ingen egen klasse å holde i synk.

Se [Tilpasning](../../customising/) for hvordan variablene og laget virker.

## Accessibility

- Radioknappen er krympet bort, ikke fjernet. `display: none` ville tatt den ut av tastaturrekkefølgen, og da virker ikke piltastene.
- Piltastene flytter mellom alternativene og velger samtidig. Tab hopper ut av hele gruppen. Slik virker radioknapper, og det skal ikke overstyres.
- Alternativene må være korte. Blir teksten lang, er det egentlig en liste med radioknapper.
- Ikke la et valg utløse noe som ikke kan angres. Brukeren treffer alle alternativene på veien når hen blar med piltastene.
