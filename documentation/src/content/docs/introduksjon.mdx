Fristil er et rammeverksuavhengig designsystem bygget for team som vil levere raskt uten å gi opp kvalitet, tilgjengelighet eller kontroll.

Målet er enkelt: gi produktteam felles språk, stabile byggeklosser og høy fart i utvikling, uansett om de bruker React, Vue, Astro, Lit eller ren HTML.

## Tre kategorier komponenter

Fristil er organisert i tre tydelige kategorier, slik at du kan velge riktig verktøy til riktig jobb:

1. **css**
	Native HTML + CSS-klasser + data-attributter. Null JavaScript-runtime. Perfekt for grunnleggende UI som knapper, typografi, spacing og fargebruk.

	Eksempel:

	```html
	<button class="ds-button" data-variant="secondary">Lagre</button>
	```

	Fordeler:

	- Minst mulig runtime og minst mulig magi.
	- Fungerer i alle rammeverk og også i ren HTML.
	- Enkelt å style, debugge og gradvis ta i bruk.

2. **ramme**
	Web Components som koordinerer native HTML-elementer du selv legger inn. Du bringer label, input og hjelpetekst — komponenten tar seg av a11y-wiring.

	Eksempel:

	```html
	<ds-field required-marker="symbol" invalid>
	  <label>E-post</label>
	  <input class="ds-input" type="email" value="ola@" />
	  <p class="ds-help-text">Vi sender aldri spam.</p>
	  <p class="ds-error-text">Skriv en gyldig e-post.</p>
	</ds-field>
	```

	Fordeler:

	- Du eier HTML-strukturen og kan tilpasse den fritt.
	- Beholder vanlig DOM, så skjemaer, testverktøy og app-logikk er enkle å koble til.
	- Passer godt når komponenten skal hjelpe med wiring, men ikke kapsle bort alt.

3. **sammensatt**
	Web Components som eier alt internt: markup, stil og interaksjon. Du sender inn attributter — komponenten gjør resten.

	Eksempel:

	```html
	<ds-date-field
	  label="Fødselsdato"
	  value="2026-05-31"
	  help-text="Skriv dato som DD-MM-YYYY eller åpne kalenderen."
	  error-text="Skriv en gyldig dato."
	></ds-date-field>
	```

	Fordeler:

	- Enklest mulig API — ingen HTML å sette opp manuelt.
	- Egner seg for komplekse interaksjoner som popup-er og kombinerte kontroller.
	- Gjør avanserte komponenter robuste og konsistente på tvers av produkter.

Denne oppdelingen gjør at du slipper "one size fits all". Du velger kategori etter kompleksitet, ikke etter trend.

## Hvorfor dele det opp slik?

Mange designsystemer prøver å løse alt med én komponentmodell. Det gir ofte enten for mye JavaScript for enkle behov, eller for lite struktur for komplekse behov.

Fristil deler derfor komponentene i kategorier:

- Enkle ting skal være enkle: en knapp trenger ikke web component-runtime.
- Rammekomponenter lar deg beholde HTML-kontrollen mens de tar hånd om wiring.
- Sammensatte komponenter kapsler kompleks interaksjon bak et enkelt attributt-API.

Fordelen med denne oppdelingen er at team kan velge riktig nivå per problem:

- Du får lavere kompleksitet i vanlige flater.
- Du får bedre gjenbruk i sammensatte mønstre.
- Du får mer robust oppførsel i avanserte interaktive komponenter.
- Du unngår at hele systemet blir dratt mot den mest kompliserte komponenttypen.

## DX: utvikleropplevelse først

God DX i Fristil handler om forutsigbarhet og flyt:

- Design tokens er én kilde til sannhet.
- CSS kan brukes direkte, uten tung integrasjon.
- TypeScript-støtte og testoppsett er lagt opp for trygg iterasjon.
- Dokumentasjonen viser både prinsipper og praktisk bruk.

Resultatet er mindre friksjon i hverdagen og færre overraskelser i produksjon.

## Tailwind-støtte

Fristil fungerer også godt med Tailwind. Du kan kombinere utility-klasser med Fristil-komponenter og tokens uten å miste konsistens i uttrykket.

For team som bruker Tailwind i dag betyr dette lav terskel for adopsjon: behold arbeidsflyten dere liker, og bygg videre på et felles designsystem i stedet for å starte fra null.

Eksempel i praksis:

```astro
---
import "@fristil/designsystem/tokens.css";
import "@fristil/designsystem/button.css";
---

<section class="mx-auto max-w-3xl p-6">
	<h2 class="mb-4 text-2xl font-bold">Handlinger</h2>
	<div class="flex flex-wrap gap-3">
		<button class="ds-button">Lagre</button>
		<button class="ds-button" data-variant="secondary">Avbryt</button>
	</div>
</section>
```

Her brukes Tailwind til layout og spacing, mens Fristil leverer komponentstil og tokens.

## Frihet og hastighet

Fristil er laget for **frihet under ansvar**. Team kan beholde egne valg i applikasjonene sine, samtidig som de bygger på et felles fundament.

Det gir to store gevinster:

- **Frihet:** bruk komponenter og stilnivå som passer konteksten din.
- **Hastighet:** gjenbruk mønstre, reduser dobbeltarbeid og lever funksjonalitet raskere.

Kort sagt: Fristil hjelper deg å bevege deg fort, uten å miste retning.
