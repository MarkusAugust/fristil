Plain CSS on an ordinary `<input type="radio">`. The buttons in a group are tied together by `name`, and that is what lets only one be selected, and lets the arrow keys move between them.

If the user can choose several, use [Checkbox](../checkbox/). If there are many options, [Select](../select/) takes less room on the screen.

`lt` is used in two ways, and which one depends on whether you create the element or find it.

**If you create the markup,** spread the attributes in. That is the way in React, Astro and anything else that renders:

```tsx
import { lt } from "@lo-tek/interfaces/react"

<div className={lt.radio.row}>
  <input {...lt.radio()} id="reply-digital" name="reply" value="digital" />
  <label {...lt.label()} htmlFor="reply-digital">Digitally</label>
</div>
```

The import is from `/react` here, since the block is JSX. From there the keys are `className` and `htmlFor`. In Astro and anything else without React, import `@lo-tek/interfaces` and you get `class` and `for`.

**If the element is already there,** set them on it. That is the way when you enhance HTML a server or a template has sent:

```ts
import { lt } from "@lo-tek/interfaces"

const buttons = document.querySelectorAll<HTMLInputElement>("[name='reply']")

function mark(invalid: boolean) {
  for (const button of buttons) {
    lt.setAttributes(button, lt.radio({ state: invalid ? "invalid" : "default" }))
  }
}
```

You set `name` yourself, since only you know what the group is called. `lt.radio.row` gives the class for the row around it. See [Type-safe use](../../type-safe-use/).

</Fragment>
</Example>

The group always belongs in a [Fieldset](../fieldset/). Without it only the option is read out, not the question it answers.

## States

<Example stiler={["radio", "label"]} layout="stabel" maxWidth="28rem" kode={`
<div class="lt-radio-row">
  <input class="lt-radio" type="radio" id="invalid-choice" name="example" data-state="invalid" aria-invalid="true" />
  <label class="lt-label" for="invalid-choice">You have to choose one option</label>
</div>
`} />

| `data-state` | Used for |
| --- | --- |
| *(omitted)* | Normal state |
| `invalid` | Validation has failed |
| `success` | The choice is confirmed valid. Use sparingly. |

If validation fails, set the state on every button in the group. It is the group that is invalid, not one of the buttons.

## Classes you can style

| Class | What it is |
| --- | --- |
| `.lt-radio` | The button itself |
| `.lt-radio-row` | The row that holds the button and the text side by side |

| Variable | Default |
| --- | --- |
| `--lt-radio-size` | `var(--lt-spacing-5)` |

The dot is a gradient drawn in `--lt-color-accent-content`, so it follows the theme without a separate image. See [Customising](../../customising/).

## Accessibility

- Every button in the group has to share `name`. Without it each button becomes its own group, and the user can choose several.
- The arrow keys move between the buttons and select at the same time. Tab leaves the whole group. That is the browser's own behaviour, and it should not be overridden.
- Do not preselect an option when the choice has a consequence. The default then becomes an answer the user never considered.
- If you only have two options that are each other's opposite, consider [Checkbox](../checkbox/) or [Switch](../switch/) instead.
