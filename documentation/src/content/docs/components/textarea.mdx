## How to use it

`lt` is used in two ways, and which one depends on whether you create the element or find it.

**If you create the markup,** spread the attributes in. That is the way in React, Astro and anything else that renders:

```tsx
import { lt } from "@lo-tek/interfaces/react"

<textarea {...lt.textarea({ state: "invalid" })} id="reason" rows={3} />
```

The import is from `/react` here, since the block is JSX. From there the keys are `className` and `htmlFor`. In Astro and anything else without React, import `@lo-tek/interfaces` and you get `class` and `for`.

**If the element is already there,** set them on it. That is the way when you enhance HTML a server or a template has sent:

```ts
import { lt, type FieldState } from "@lo-tek/interfaces"

const field = document.querySelector<HTMLTextAreaElement>("#reason")
if (!field) throw new Error("element not found")

field.addEventListener("blur", () => {
  const state: FieldState = field.value.trim().length >= 20 ? "success" : "invalid"

  lt.setAttributes(field, lt.textarea({ state }))
})
```

`state` is the same type as in [Input](../input/) and [Select](../select/), so the value can be passed between them. `lt.setAttributes` clears the state from the previous call, so the field does not stay red after the error is fixed.

| `data-state` | Used for |
| --- | --- |
| *(omitted)* | Normal state |
| `invalid` | Validation has failed |
| `success` | The content is confirmed valid |

`data-state` is colour. Screen readers need `aria-invalid="true"` as well, or [Field](../field/), which sets both.

## Classes you can style

| Class | What it is |
| --- | --- |
| `.lt-textarea` | The field. The state comes from `data-state`. |

| Variable | Default |
| --- | --- |
| `--lt-textarea-min-height` | `calc(var(--lt-spacing-4) * 5)` |
| `--lt-textarea-padding` | `var(--lt-spacing-2) var(--lt-spacing-3)` |
| `--lt-textarea-radius` | `var(--lt-spacing-1)` |

`--lt-textarea-min-height` is a minimum height, not a fixed height. `rows` works above it, and the user can still drag the field taller. With the default font and padding the minimum height is a little under three rows, so `rows="1"` and `rows="2"` give the same field, and only `rows="3"` is taller. If `rows` alone should decide the height, set `--lt-textarea-min-height: 0`. The width is locked, since the class sets `resize: vertical`.

See [Customising](../../customising/) for how the variables and the layer work.

## Accessibility

- Every field needs a visible `<label>` with `for` pointing to the `id`.
- If the field has an upper limit, say so in the help text before the user types. `maxlength` alone blocks typing without explaining why.
- If you use a character counter, put it in an element with `aria-live="polite"` and let it announce only when the limit is near. Otherwise it interrupts the reading on every keystroke.
- Do not turn off `resize`. It is often the only way the user gets an overview of a long text.
