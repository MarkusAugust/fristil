Klassen settes på et vanlig `<button>`. Ingen JavaScript lastes, og den virker likt i alle rammeverk.

## Slik tar du den i bruk

`lt` brukes på to måter, og hvilken avhenger av om du lager elementet eller finner det.

**Lager du markupen,** sprer du attributtene inn. Det er veien i React, Astro og alt annet som rendrer:

```tsx
import { lt } from "@lo-tek/interfaces/react"

<button {...lt.button()}>Send søknad</button>
```

Importen går til `/react` her, siden blokka er JSX. Derfra heter nøklene `className` og `htmlFor`. I Astro og alt annet uten React importerer du `@lo-tek/interfaces` og får `class` og `for`.

**Står elementet der fra før,** setter du dem på det. Det er veien når du forbedrer HTML en server eller en mal har sendt:

```ts
import { lt } from "@lo-tek/interfaces"

const knapp = document.querySelector<HTMLButtonElement>("#send")

lt.setAttributes(knapp, lt.button({ variant: "secondary" }))
```

`lt.button()` uten argument gir primærknappen, som ikke trenger noe `data-variant`.

Kommer varianten fra et API eller en URL, valider den:

```ts
import { lt, type ButtonVariant } from "@lo-tek/interfaces"

const variant: ButtonVariant = lt.button.isVariant(svar.variant)
  ? svar.variant
  : "primary"

lt.setAttributes(knapp, lt.button({ variant }))
```

Se [Typesikker bruk](../../type-safe-use/).

**Gjenbrukbar knapp i React.**

```tsx
import { lt } from "@lo-tek/interfaces/react"
import type { ButtonVariant } from "@lo-tek/interfaces"
import type { ComponentProps } from "react"

type Props = ComponentProps<"button"> & {
  variant?: ButtonVariant
}

export function Knapp({ variant, className, ...rest }: Props) {
  const knapp = lt.button({ variant })
  return (
    <button
      {...knapp}
      {...rest}
      className={className ? `${knapp.className} ${className}` : knapp.className}
    />
  )
}
```

`className` slås sammen med systemets klasse. Spres den bare inn etter `lt.button()`, erstatter den `lt-button`, og knappen mister stilen uten at noe sier fra.

Bytter teamet rammeverk, er det denne ene komponenten som skrives om, ikke designsystemet.

`ComponentProps<"button">` tar med `ref`, som siden React 19 er en vanlig prop og følger med gjennom `{...rest}` uten `forwardRef`. `ComponentPropsWithRef` og `ComponentPropsWithoutRef` trengs ikke lenger.

| `data-variant` | Brukes til |
| --- | --- |
| *(utelatt)* | Hovedhandlingen på siden. Bruk bare én. |
| `secondary` | Alternativ handling ved siden av hovedhandlingen |
| `ghost` | Lav vekt, for verktøylinjer, handlinger i tabeller og kort |
| `danger` | Sletter eller kan ikke angres |

## Deaktivert

<Example stiler={["button"]} kode={`
<button class="lt-button" disabled>Send søknad</button>
<button class="lt-button" data-variant="secondary" disabled>Lagre utkast</button>
<a class="lt-button" role="link" tabindex="0" aria-disabled="true">Gå til oversikten</a>
`} />

`disabled` finnes bare på `<button>`. Er knappen en `<a>`, bruk `aria-disabled="true"` og ta bort `href`, ellers følger Enter den. Skriv `role="link"` og `tabindex="0"` ved siden av, så skjermlesere fortsatt finner lenken og kan si at den er utilgjengelig. Se [Link](../link/#deaktivert-lenke).

## Lenke som ser ut som knapp

<Example stiler={["button"]} kode={`
<a class="lt-button" href="#">Gå til oversikten</a>
<a class="lt-button" data-variant="secondary" href="#">Les vilkårene</a>
`} />

Navigerer du brukeren, skal elementet være en `<a>` selv om det ser ut som en knapp. Da virker høyreklikk, midtklikk og «åpne i ny fane».

## På smal skjerm

Knappeteksten brekker når den må. En knapp med en lang norsk ledetekst, som «Send søknaden om bostøtte for hele kalenderåret 2026», ville ellers blitt bredere enn telefonen, og da ruller hele siden sidelengs.

Trenger du en knapp i full bredde, er det appens oppsett:

```css
.skjema-knapp {
	inline-size: 100%;
}
```

## Klasser du kan style

| Klasse | Hva det er |
| --- | --- |
| `.lt-button` | Knappen. Varianten kommer fra `data-variant`. |

| Variabel | Standard |
| --- | --- |
| `--lt-button-padding` | `var(--lt-spacing-2) var(--lt-spacing-4)` |
| `--lt-button-radius` | `var(--lt-spacing-1)` |
| `--lt-button-border-width` | `1px` |
| `--lt-button-font-weight` | `var(--lt-font-weight-medium)` |
| `--lt-button-line-height` | `var(--lt-line-height-default)` |

```css
:root {
	--lt-button-radius: 9999px;
}
```

Et eksempel. En knapp som skal stå i en tabellrad trenger mindre luft enn en som står alene:

<Example stiler={["button"]} layout="rad" egenCss={`
.rad-knapp {
	--lt-button-padding: var(--lt-spacing-1) var(--lt-spacing-3);
	--lt-button-radius: var(--lt-spacing-4);
}
`} kode={`
<button class="lt-button">Åpne saken</button>
<button class="lt-button rad-knapp" data-variant="secondary">Åpne</button>
`} />

Klassen `rad-knapp` er din. Systemet kjenner den ikke, og den virker fordi variabelen arves ned i knappen.

Standardverdien følger `--lt-spacing-*`-skalaen, så knappen holder seg i takt med resten når du skriver om skalaen, trinn for trinn. Se [Tilpasning](../../customising/).

## Tilgjengelighet

- `<button>` utfører en handling, `<a>` flytter deg et annet sted. Velg etter hva som skjer, ikke hvordan det ser ut.
- Inne i et `<form>` er `type="submit"` standard. Skal knappen ikke sende skjemaet, skriv `type="button"`.
- La teksten beskrive handlingen: «Slett bruker» sier mer enn «OK».
- Ikke bruk en deaktivert knapp som eneste forklaring på hvorfor noe ikke går. Vis en feilmelding brukeren kan gjøre noe med.
