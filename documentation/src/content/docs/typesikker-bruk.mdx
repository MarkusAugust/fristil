CSS-komponentene styres med klasser og dataattributter. Det gjør dem uavhengige av rammeverk, men det betyr også at alt er strenger:

```html
<button class="fs-button" data-variant="secundary">Lagre utkast</button>
```

Knappen over får primærstilen. Ingen feilmelding, ingen advarsel — bare en variant som stille aldri ble brukt. Slike feil overlever kodegjennomgang fordi de ser riktige ut.

Hver CSS-komponent eksporterer derfor tre ting som gjør den samme kontrakten typet.

## De tre delene

**En type med de gyldige verdiene.** `ButtonVariant` er `"primary" | "secondary" | "ghost" | "danger"`. Editoren foreslår dem, og `"secundary"` blir rød.

**En funksjon som lager attributtene.** `getButtonStyleAttributes()` returnerer objektet du sprer inn i elementet.

**En vaktfunksjon for verdier utenfra.** `isButtonVariant()` sjekker om en vilkårlig streng er en gyldig variant.

```ts
import {
	getButtonStyleAttributes,
	isButtonVariant,
	type ButtonVariant,
} from "@fristil/designsystem/button"
```

## Lage attributtene

```ts
getButtonStyleAttributes("secondary")
// { class: "fs-button", "data-variant": "secondary" }

getButtonStyleAttributes("primary")
// { class: "fs-button" }
```

Primærvarianten gir ikke noe `data-variant`, fordi den er standard i CSS-en. Det er én ting mindre å holde styr på: du sier alltid hvilken variant du vil ha, og funksjonen vet når attributtet kan utelates.

## Bare Fristils del

Funksjonene returnerer utelukkende Fristils egne attributter. Alt annet på elementet eier appen din:

```ts
const attributter = {
	...getButtonStyleAttributes("danger"),
	type: "submit",
	"aria-label": "Slett søknaden permanent",
	onClick: slettSøknad,
}
```

Det betyr at det ikke finnes noe «Fristil-knappekomponent-API» å lære. Du lager et vanlig `<button>`, og henter stil-delen fra en funksjon.

## Verdier som kommer utenfra

Kommer varianten fra et API, en URL-parameter eller `localStorage`, er den en `string` TypeScript ikke kan garantere noe om. Vaktfunksjonen gjør den om til en gyldig verdi eller en trygg reserve:

```ts
import {
	getButtonStyleAttributes,
	isButtonVariant,
} from "@fristil/designsystem/button"

const svar = await hentKnappeoppsett()
const variant = isButtonVariant(svar.variant) ? svar.variant : "primary"

getButtonStyleAttributes(variant)
```

Etter `isButtonVariant(...)` vet TypeScript at `svar.variant` er en `ButtonVariant`, ikke bare en `string`. Er verdien ukjent, får du primærknappen i stedet for et dataattributt ingen CSS-regel treffer.

## Samme mønster overalt

Alle CSS-komponentene følger den samme formen. Kan du én, kan du resten:

| Komponent | Lag attributter | Valider verdi | Type |
| --- | --- | --- | --- |
| [Button](../components/button/) | `getButtonStyleAttributes` | `isButtonVariant` | `ButtonVariant` |
| [Input](../components/input/) | `getInputStyleAttributes`, `getInputAttributes` | `isInputState`, `isInputVariant` | `InputState`, `InputVariant` |
| [Label](../components/label/) | `getLabelStyleAttributes` | `isLabelRequiredMarker` | `LabelRequiredMarker` |
| [Select](../components/select/) | `getSelectStyleAttributes` | `isSelectState` | `SelectState` |
| [Textarea](../components/textarea/) | `getTextareaStyleAttributes` | `isTextareaState` | `TextareaState` |
| [Help Text](../components/help-text/) | `getHelpTextStyleAttributes` | `isHelpTextVariant` | `HelpTextVariant` |
| [Error Text](../components/error-text/) | `getErrorTextStyleAttributes` | `isErrorTextVariant` | `ErrorTextVariant` |

[Input](../components/input/) har i tillegg `getInputAttributes`, som også setter `type`. Det holder `type="date"` og `data-variant="date"` i takt — et par som må stemme for at ikonet i feltet skal åpne datovelgeren.

## I praksis: en gjenbrukbar knapp i React

```tsx
import {
	getButtonStyleAttributes,
	type ButtonVariant,
} from "@fristil/designsystem/button"
import type { ComponentProps } from "react"

type Props = ComponentProps<"button"> & {
	variant?: ButtonVariant
}

export function Knapp({ variant = "primary", ...rest }: Props) {
	return <button {...getButtonStyleAttributes(variant)} {...rest} />
}
```

Komponenten er tolv linjer og har ingen Fristil-avhengighet utover den ene importen. Bytter teamet rammeverk, er det disse tolv linjene som skrives om — ikke designsystemet.

Samme mønster i Vue, Svelte eller Angular ser praktisk talt likt ut. Funksjonen returnerer et objekt, og alle rammeverk kan spre et objekt inn i et element.

## Når du kan hoppe over det

Hjelperne er valgfrie. Skriver du HTML for hånd, i en mal uten TypeScript, eller i et oppsett uten byggesteg, er dette like gyldig:

```html
<button class="fs-button" data-variant="secondary">Lagre utkast</button>
```

Resultatet er identisk. Forskjellen er bare hvor tidlig du får vite at du skrev `secundary`.
