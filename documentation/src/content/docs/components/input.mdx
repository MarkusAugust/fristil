`fs-input` gir `<input>` felles utseende, fokusmarkering og tilstander. Det er ren CSS på et vanlig input-element, så nettleserens egen validering, autofyll og tastaturhåndtering virker akkurat som før.

## Importer

```js
import "@fristil/designsystem/tokens.css"
import "@fristil/designsystem/input.css"
```

## Tilstander

`data-state` sier hva valideringen har konkludert med. Utelater du attributtet, er feltet i normaltilstand.

`data-state="invalid"` er bare farge. Skjermlesere trenger `aria-invalid="true"` i tillegg — eller [Field](../field/), som setter begge for deg.

## Dato og klokkeslett

`data-variant` legger et ikon inne i feltet for dato- og tidstyper. Nettleserens egen velger beholdes som den er.

      <label class="fs-label" for="ex-dato">Reisedato</label>
      <input class="fs-input" id="ex-dato" data-variant="date" type="date" value="2026-05-31" />

      <label class="fs-label" for="ex-tid">Avreisetidspunkt</label>
      <input class="fs-input" id="ex-tid" data-variant="time" type="time" value="14:30" />
    </Preview>
  </TabItem>
  <TabItem label="Kode">
    ```html
    <input class="fs-input" data-variant="date" type="date" />
    <input class="fs-input" data-variant="time" type="time" />
    <input class="fs-input" data-variant="datetime-local" type="datetime-local" />
    ```
  </TabItem>
</Tabs>

:::caution[`data-variant` og `type` må være like]
Ikonet styres av `data-variant`, mens velgeren som åpnes styres av `type`. Setter du bare den ene, får du et felt som ser ut som et datofelt, men der ingenting skjer når brukeren trykker på ikonet.

```html
<!-- Riktig -->
<input class="fs-input" data-variant="date" type="date" />

<!-- Feil: ikonet vises, men åpner ingenting -->
<input class="fs-input" data-variant="date" type="text" />
```
:::

Støttede verdier for `data-variant`: `text`, `password`, `email`, `number`, `date`, `datetime-local`, `week`, `month`, `tel`, `url`, `search` og `time`. Bare `date`, `time` og `datetime-local` påvirker utseendet — resten finnes for at TypeScript-hjelperen skal kunne sette `type` for deg.

## Hvilken komponent skal du bruke til dato?

| Situasjon | Komponent |
| --- | --- |
| Nettleserens egen datovelger holder | **Input** med `type="date"` |
| Du trenger et kalenderpanel du styrer selv | [Calendar](../calendar/) |
| Du vil ha ledetekst, hjelpetekst, feilmelding og kalender ferdig koblet | [Date Field](../date-field/) |

## TypeScript

```ts
import { fs } from "@fristil/designsystem"

fs.input({ type: "email" })
// { class: "fs-input", type: "email" }

fs.input({ type: "date" })
// { class: "fs-input", type: "date", "data-variant": "date" }

fs.input({ state: "invalid" })
// { class: "fs-input", type: "text", "data-state": "invalid", "aria-invalid": "true" }
```

Dette løser de to fellene på denne siden. `type` styrer både HTML-typen og ikonvarianten, så de kan ikke komme i utakt. Og `state: "invalid"` setter `aria-invalid` sammen med fargen, så skjermleseren aldri blir glemt.

Resten av elementet eier du:

```ts
<input {...fs.input({ type: "email", state })} id="epost" name="epost" required />
```

## Verdier som kommer utenfra

Kommer tilstand eller type fra et API, en URL-parameter eller `localStorage`, er det vanlige strenger. Valider dem før de treffer skjermen:

```ts
const svar = await hentFeltoppsett()

const state = fs.input.isState(svar.state) ? svar.state : "default"
const type = fs.input.isType(svar.type) ? svar.type : "text"

fs.input({ type, state })
```

Er `svar.type` for eksempel `"birthday"`, faller den tilbake til `"text"` i stedet for å sette en `type` nettleseren ikke kjenner.

## Tilgjengelighet

- Hvert felt trenger en synlig `<label>` med `for` som peker på `id`-en. `placeholder` er ikke en erstatning — den forsvinner idet brukeren begynner å skrive.
- Sett `aria-invalid="true"` sammen med `data-state="invalid"`, og koble feilmeldingen til feltet med `aria-describedby`.
- Bruk riktig `type` (`email`, `tel`, `url`, `number`). Det bestemmer hvilket tastatur mobilbrukere får opp, og hva nettleseren tilbyr av autofyll.
- Sett `autocomplete` på felt som spør om personopplysninger, for eksempel `autocomplete="email"`. Det sparer brukeren for skriving og reduserer feil.
