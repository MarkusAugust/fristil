Panelet bruker nettleserens egen `popover`, så det havner i topplaget og legger seg over alt annet uten at noen trenger å finne en `z-index` som er høy nok.

Resten gjør komponenten. Panelet åpnes i `manual`-modus, ikke `auto`, siden nettleserens egen lukking rekker å lukke panelet før knappen får klikket sitt, og knappen da ikke kan brukes til å lukke igjen. Escape, klikk utenfor og fokus tilbake til knappen er derfor skrevet i komponenten. Skriver du `popover` uten verdi for hånd, er panelet `auto`, og da følger komponenten med når nettleseren lukker det.

Plasseringen er også vår. `position-anchor` finnes ennå ikke i alle nettlesere, så komponenten regner ut posisjonen mot knappen og setter den som to variabler på panelet.

:::note[To veier til den samme markupen]
Lages markupen med JavaScript, gir `lt.popover()` koblingen mellom knapp og panel, id-en og `popover`-attributtet, ferdig i HTML-en. Blir den til uten JavaScript, holder det med en knapp og et panel med klassen `lt-popover` og en id: komponenten setter `popover="manual"` og skriver `aria-controls` på knappen. Id-en skriver malen, siden `aria-controls` peker på den. Komponenten lager aldri en: et panel med en id serveren ikke sendte, ble byttet ut ved neste oppdatering, med fokus. Mangler id-en, virker vinduet, men knappen er ikke koblet til panelet, og komponenten, `lotek sjekk` og editorene sier fra. Posisjonen, Escape og klikk utenfor kommer fra komponenten i begge tilfeller. Se [Markup og oppførsel](/markup-and-behaviour/#byggefunksjon-eller-web-component).
:::

// main.ts, kjøres én gang når appen starter
import { defineLtPopover } from "@lo-tek/interfaces/popover"
import "@lo-tek/interfaces/tokens.css"

defineLtPopover()

    import { useRef } from "react"
    import { lt } from "@lo-tek/interfaces/react"
    import "@lo-tek/interfaces/tokens.css"

    export function Handlingsmeny({ påArkiver }: { påArkiver: () => void }) {
      const meny = useRef<HTMLElement & { hide(): void }>(null)
      const boks = lt.popover({ id: "handlinger", placement: "bottom-end" })

      const velg = (handling: () => void) => () => {
        handling()
        meny.current?.hide()
      }

      return (
        <lt-popover ref={meny} {...boks.host}>
          <button {...boks.trigger} {...lt.button({ variant: "secondary" })}>
            Handlinger
          </button>

          <ul {...boks.panel}>
            <li>
              <button {...lt.button({ variant: "ghost" })} onClick={velg(påArkiver)}>
                Arkiver saken
              </button>
            </li>
          </ul>
        </lt-popover>
      )
    }

```html
<lt-popover placement="bottom-end">
  <button class="lt-button" data-variant="secondary" type="button"
          aria-expanded="false" aria-controls="handlinger">Handlinger</button>

  <ul class="lt-popover" id="handlinger" popover="manual">
    <li><button class="lt-button" data-variant="ghost" type="button">Arkiver saken</button></li>
    <li><button class="lt-button" data-variant="ghost" type="button">Last ned som PDF</button></li>
  </ul>
</lt-popover>
```

Komponenten kjenner igjen panelet på `popover` eller klassen `lt-popover`, og knappen på `aria-controls` som peker på panelet, ellers på at den er den første knappen utenfor panelet som ikke peker på noe annet med `aria-controls`.

Lages markupen med JavaScript, skriver `lt.popover()` koblingen, id-en, klassen og `popover`. Kommer den fra en mal uten JavaScript, skriver malen id-en på panelet, og komponenten setter `popover="manual"` og `aria-controls`, og lar det serveren har skrevet stå. Komponenten setter dessuten `open` på verten, `aria-expanded` på knappen og posisjonen på panelet. Alt den har skrevet setter den tilbake når en oppdatering fra serveren river det bort.

Reparasjonen gjelder én vei: har noen bedt om at vinduet er åpent, blir det stående. Sender serveren `open`, åpnes det, for det er noe serveren faktisk sa.

Lukk med egenskapen, altså `meny.open = false`, `hide()` eller `toggle()`. Det er en beskjed komponenten kan se. Forskjellen mellom dem er hendelsen: `hide()` og `toggle()` sender `popover-toggle`, egenskapen gjør det ikke. Fjerner du attributtet utenfra i stedet, som med Datastars `data-attr:open`, er det ikke til å skille fra en oppdatering som river det bort, og da setter komponenten det tilbake. Der er `server-controlled` svaret. Se [Markup og oppførsel](/markup-and-behaviour/).

## Attributter

| Attributt | Type | Effekt |
| --- | --- | --- |
| `open` | boolsk | Om panelet er åpent. Speiles når brukeren åpner og lukker. |
| `placement` | streng | `bottom-start`, `bottom-end`, `top-start` eller `top-end`. `start` og `end` følger leseretningen, så i en side med `dir="rtl"` er `start` høyre kant. Er det ikke plass langs kanten, skyves panelet inn i vinduet framfor å bytte andre. `lt.popover({ id, placement })` skriver det på verten, `lt.popover.isPlacement` sjekker en verdi, og `popoverPlacements` fra hovedinngangen lister dem |
| `server-controlled` | boolsk | Serveren bestemmer om panelet er åpent. Komponenten setter ikke `open` tilbake når en oppdatering fra serveren fjerner det, slik den gjør uten attributtet. |

## Hendelser og metoder

| Navn | Hva det er |
| --- | --- |
| `popover-toggle` | Hendelse med `{ open: boolean }` i `detail`. Sendes når brukeren åpner eller lukker panelet, og fra `show()`, `hide()` og `toggle()`, ikke når `open` settes som egenskap eller attributt |
| `show()`, `hide()`, `toggle()` | Metoder på elementet |

```js
const meny = document.querySelector("lt-popover")

meny.addEventListener("popover-toggle", (hendelse) => {
  console.log(hendelse.detail.open ? "åpnet" : "lukket")
})
```

Panelet flytter seg med siden når brukeren ruller eller endrer vindusstørrelsen. Er det ikke plass under knappen, legger det seg over.

## Klasser du kan style

Komponenten rendrer i vanlig DOM, så markupen din treffes av vanlige selektorer:

| Klasse | Hva det er |
| --- | --- |
| `.lt-popover` | Panelet. Komponenten kjenner det igjen på klassen eller på `popover`, og fyller inn den andre |

| Variabel | Standard |
| --- | --- |
| `--lt-popover-width` | `min(20rem, calc(100vw - var(--lt-spacing-8)))`, den største bredden. Panelet er så bredt som innholdet, opp til denne |
| `--lt-popover-padding` | `var(--lt-spacing-3)` |
| `--lt-popover-radius` | `var(--lt-spacing-1)` |
| `--lt-popover-top` | settes av komponenten |
| `--lt-popover-left` | settes av komponenten |

Posisjonen settes som `--lt-popover-top` og `--lt-popover-left` på elementet. De to er regnet ut fra knappens plass på skjermen, og er de eneste verdiene komponenten skriver inn direkte. Alt annet står i stilarket, så du kan overstyre det uten `!important`.

Se [Tilpasning](../../customising/) for hvordan variablene og laget virker.

## Tilgjengelighet

- Panelet er ikke en dialog. Fokus flyttes ikke inn automatisk, og resten av siden er fortsatt i bruk. Trenger du å stoppe brukeren, bruk [Dialog](../dialog/).
- Escape lukker og gir fokus tilbake til knappen. Uten det står fokus på noe som ikke finnes lenger.
- Innholdet i panelet skal kunne nås med Tab, i samme rekkefølge som det står i markupen.
- Ikke legg et skjema som må fylles ut i et panel som lukker seg ved klikk utenfor.
