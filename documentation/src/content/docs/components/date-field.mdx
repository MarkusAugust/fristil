Et komplett datofelt: ledetekst, tekstfelt, hjelpetekst, feilmelding og [Calendar](../calendar/), bygget og holdt i synk av komponenten. Du sender inn attributter.

## Hvilken datokomponent?

| Situasjon | Komponent |
| --- | --- |
| Nettleserens egen datovelger holder | [Input](../input/) med `type="date"` |
| Du trenger et kalenderpanel du styrer selv | [Calendar](../calendar/) |
| Du vil ha felt, ledetekst, hjelpetekst og kalender ferdig koblet | **Date Field** |

Standardvalget for datoer i skjema.

```ts
// main.ts – kjøres én gang når appen starter
```

## To formater

`value` er alltid ISO — `ÅÅÅÅ-MM-DD`. Feltet viser `DD-MM-ÅÅÅÅ`. Komponenten oversetter begge veier, så du forholder deg bare til ISO.

Parse aldri teksten i feltet selv. Les `value`.

## Validering

Komponenten sjekker om datoen finnes, når feltet mister fokus. Er den umulig, som `32-06-2026`, vises `error-text`.

Alt annet — fortid, intervall, virkedag — er din regel, satt med `invalid`:

```js
const felt = document.getElementById("reisedato")

felt.addEventListener("change", () => {
	const forTidlig = felt.value !== "" && felt.value < "2026-06-01"
	felt.toggleAttribute("invalid", forTidlig)
})
```

ISO lar datoer sammenlignes som strenger: `"2026-05-31" < "2026-06-01"` er sant.

    ```html
      const iDag = new Date().toISOString().slice(0, 10)
    ```

    ```tsx
      return (

            name="reisedato"

            help-text="Skriv datoen som DD-MM-ÅÅÅÅ, eller velg den i kalenderen."
            error-text="Velg en dato fram i tid."
            onChange={(e) => {
              const element = e.currentTarget as HTMLElement & { value: string }
              setDato(element.value)
            }}
          />

          <button className="fs-button" type="submit">Bestill</button>
        </form>
      )
    ```

    `e.currentTarget.value` er ISO — les den, ikke teksten i feltet.

    :::caution[`invalid={ugyldig || undefined}` — ikke noe annet]
    React behandler egendefinerte elementer ulikt mellom versjoner, og bare dette mønsteret er riktig i begge:

    | | React 18 (setter attributt) | React 19 (setter egenskap) |
    | --- | --- | --- |
    | `invalid=""` | virker | **aldri ugyldig** |
    | `invalid={ugyldig}` | **alltid ugyldig** | virker |
    | `invalid={ugyldig \|\| undefined}` | virker | virker |

    Importerer du `@fristil/designsystem/react-jsx`, blir de to andre variantene kompileringsfeil.
    :::

    ```html
    <form data-signals="{dato: '2026-05-31'}">
      <fs-date-field
        label="Reisedato"
        name="reisedato"
        value="2026-05-31"
        help-text="Skriv datoen som DD-MM-ÅÅÅÅ, eller velg den i kalenderen."
        error-text="Velg en dato fram i tid."
        data-on:change="$dato = evt.currentTarget.value"
        data-attr:invalid="$dato !== '' && $dato < new Date().toISOString().slice(0, 10)"
      ></fs-date-field>

      <p>Valgt dato: <span data-text="$dato"></span></p>

      <button class="fs-button" type="submit">Bestill</button>
    </form>

    <script type="module">
      import { defineFsDateField } from "@fristil/designsystem/date-field"
      defineFsDateField()
    </script>
    ```

    Bruk `evt.currentTarget`, ikke `evt.target`. Komponenten rendrer et `<input>` inni seg, og hendelsen bobler derfra — `evt.target` er altså tekstfeltet, og verdien der er `DD-MM-ÅÅÅÅ`. `currentTarget` er `<fs-date-field>` selv, og den gir alltid ISO.

    `data-attr:invalid` setter og fjerner attributtet etter uttrykket, så du slipper å tenke på hvordan rammeverket oversetter boolske verdier.

## Attributter

| Attributt | Type | Hva det gjør |
| --- | --- | --- |
| `label` | streng | Synlig ledetekst. Standard: `Dato` |
| `value` | streng | Datoen som `ÅÅÅÅ-MM-DD`. Speiles til attributtet. |
| `name` | streng | Navnet feltet sendes under i skjemaet |
| `placeholder` | streng | Standard: `DD-MM-YYYY` |
| `help-text` | streng | Forklarende tekst under feltet |
| `error-text` | streng | Feilmeldingen som vises når feltet er ugyldig |
| `invalid` | boolsk | Setter ugyldig tilstand og viser `error-text` |
| `required` | boolsk | Markerer ledeteksten som påkrevd og setter `required` på feltet |
| `optional` | boolsk | Markerer ledeteksten som valgfri |
| `disabled` | boolsk | Deaktiverer både feltet og kalenderen |
| `readonly` | boolsk | Gjør feltet skrivebeskyttet |
| `control-id` | streng | Bestemmer `id`-en på feltet i stedet for å la komponenten lage en |
| `described-by` | streng | Legger til ekstra `id`-er i `aria-describedby` |

## Hendelser

| Hendelse | Når den sendes |
| --- | --- |
| `input` | Når verdien endres, enten brukeren skriver eller velger i kalenderen |
| `change` | Samtidig med `input` |

Begge bobler. Les alltid `element.value` — den er ISO uansett hvordan datoen ble satt.

## Tastatur

| Tast | Virkning |
| --- | --- |
| `Mellomrom` eller `Pil ned` i feltet | Åpner kalenderpanelet |
| Piltaster i panelet | Flytter mellom dagene |
| `Escape` i panelet | Lukker panelet |

Velges en dag i panelet, går fokus tilbake til tekstfeltet.

## Tilgjengelighet

- Komponenten setter `for`, `aria-describedby` og `aria-invalid` selv. Du trenger ikke røre dem.
- `error-text` må si hva brukeren skal gjøre. «Skriv en dato som finnes, for eksempel 31-05-2026» hjelper der «Ugyldig dato» bare bekrefter at noe er galt.
- `help-text` bør nevne formatet. Brukere som skriver raskere enn de klikker, treffer ofte `31.05.2026` eller `2026-05-31` på første forsøk.
- Kalenderen er et tillegg, ikke veien inn. Feltet kan alltid fylles ut med tastatur alene.
- Se forbeholdet om fokus ved lukking av kalenderpanelet på [Calendar](../calendar/#tastatur-og-tilgjengelighet).
