En boks som sier noe om helheten: at søknaden ble sendt, at tjenesten er nede, at fristen nærmer seg. Gjelder meldingen ett felt, hører den hjemme under feltet som [Error Text](../error-text/) eller [Help Text](../help-text/).

`lt` brukes på to måter, og hvilken avhenger av om du lager elementet eller finner det.

**Lager du markupen,** sprer du attributtene inn. Det er veien i React, Astro og alt annet som rendrer:

```tsx
import { lt } from "@lo-tek/interfaces/react"

<div {...lt.alert({ color: "success" })}>
  <p>Søknaden er sendt. Kvittering er på vei til e-posten din.</p>
</div>
```

Importen går til `/react` her, siden blokka er JSX. Derfra heter nøklene `className` og `htmlFor`. I Astro og alt annet uten React importerer du `@lo-tek/interfaces` og får `class` og `for`.

**Står elementet der fra før,** setter du dem på det. Det er veien når du forbedrer HTML en server eller en mal har sendt:

```ts
import { lt, type AlertColor } from "@lo-tek/interfaces"

const boks = document.querySelector<HTMLElement>("#status")
if (!boks) throw new Error("fant ikke elementet")

// Pilfunksjon, ikke `function`: en hoistet funksjonsdeklarasjon arver ikke
// innsnevringen av `boks` over, og da er den `null` igjen inne i kroppen.
const vis = (farge: AlertColor, tekst: string) => {
  lt.setAttributes(boks, lt.alert({ color: farge }))
  boks.textContent = tekst
}
```

Kommer fargen fra et svar utenfra, valider den med `lt.alert.isColor(x)`. `lt.alert.title` gir klassen på overskriften. Se [Typesikker bruk](../../type-safe-use/).

| `data-color` | Brukes til |
| --- | --- |
| *(utelatt)* | Nøytral opplysning |
| `info` | Noe brukeren bør vite, men som ikke krever handling |
| `success` | Noe gikk bra |
| `warning` | Noe krever oppmerksomhet, men stopper ingenting |
| `danger` | Noe gikk galt, eller stopper brukeren |

## Rolle når meldingen kommer underveis

Rollen er ikke en del av `data-color`, fordi den avhenger av *når* meldingen kommer, ikke av hva den betyr.

| Situasjon | Hva du setter |
| --- | --- |
| Meldingen står i markupen når siden lastes | Ingen rolle |
| Meldingen dukker opp mens brukeren holder på | `role="status"` |
| Brukeren må stoppe og gjøre noe nå | `role="alert"` |

```html
<div class="lt-alert" data-color="danger" role="alert">
  <p class="lt-alert__title">Søknaden ble ikke sendt</p>
  <p>Nettverket svarte ikke. Prøv igjen om litt.</p>
</div>
```

`role="alert"` avbryter det skjermleseren holder på med. Bruk den bare når avbruddet er berettiget. `role="status"` venter til brukeren er ferdig med setningen sin.

Elementet må stå i DOM-en før du fyller det med tekst. Legger du inn hele boksen ferdig utfylt, rekker ikke skjermleseren å se endringen.

## Klasser du kan style

| Klasse | Hva det er |
| --- | --- |
| `.lt-alert` | Selve boksen. Fargen kommer fra `data-color`. |
| `.lt-alert__title` | Overskriften inne i boksen |

| Variabel | Standard |
| --- | --- |
| `--lt-alert-padding` | `var(--lt-spacing-3) var(--lt-spacing-4)` |
| `--lt-alert-radius` | `var(--lt-spacing-1)` |
| `--lt-alert-accent` | `var(--lt-spacing-1)`, bredden på streken langs kanten |

Hver farge har en strek på kanten og en svak flate bak teksten, og brødteksten holder kontrasten mot den flaten i begge temaer. Se [Tilpasning](../../customising/).

## Tilgjengelighet

- Fargen alene sier ingenting. Teksten må bære beskjeden også for den som ikke ser forskjell på grønt og rødt.
- Én melding om gangen. Tre bokser over hverandre leses som støy, og brukeren finner ikke den som gjelder.
- Si hva brukeren skal gjøre. «Prøv igjen om litt» hjelper der «En feil oppstod» ikke gjør det.
- Skal meldingen kunne lukkes, gi lukkeknappen en tekst som sier hva som lukkes, ikke bare et kryss.
