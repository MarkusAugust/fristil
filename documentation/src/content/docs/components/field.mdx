`<fs-field>` er en rammekomponent bygget med Lit. Du legger dine egne native elementer inn i den, og komponenten tar seg av a11y-wiring.

## Hvorfor `defineDsField()`?

`defineDsField()` registrerer custom elementet i nettleseren:

- Før registrering: `<fs-field>` er bare en ukjent HTML-tag.
- Etter registrering: `<fs-field>` blir en ekte web component med logikken sin.

Du trenger å kalle `defineDsField()` **én gang** når appen starter.
Hvis du kaller den flere ganger, skjer ingenting (den er beskyttet mot dobbel registrering).

## Import

```ts
import { defineDsField } from "@fristil/designsystem/field"
import "@fristil/designsystem/field.css"

// Kall én gang i app-entry (main.ts, app.ts, e.l.)
defineDsField()
```

## Kom i gang (3 steg)

1. Importer `field.css` (inkluderer label, input, textarea, select, help-text og error-text).
2. Kjør `defineDsField()` én gang i app-start.
3. Bruk `<fs-field>` rundt `label` + ett felt (`input`, `select` eller `textarea`).

Komponenten gjør dette automatisk:

1. Setter `label[for]` til control-id.
2. Genererer id på help/error ved behov.
3. Setter `aria-describedby` på kontrollen.
4. Setter `aria-invalid="true"` når `invalid` er satt.
5. Setter `data-required`/`data-optional` på label via wrapper-attributter.
6. Viser eller skjuler `fs-error-text` automatisk basert på `invalid`.

## Minste eksempel

```html
<fs-field>
  <label>Navn</label>
  <input class="fs-input" type="text" />
</fs-field>
```

Dette gir deg automatisk kobling mellom label og input uten at du manuelt må holde styr på `for`/`id`.

## Bruk i en app

        <p class="fs-error-text">Navn er påkrevd.</p>

    <script type="module">
      const form = document.getElementById('contact-form')
      const nameField = document.getElementById('name-field')

      form.addEventListener('submit', (e) => {
        e.preventDefault()
        const input = nameField.querySelector('input')
        if (!input.value.trim()) {
          nameField.setAttribute('invalid', '')
        } else {
          nameField.removeAttribute('invalid')
          // prosesser skjemaet...
        }
      })
    </script>
    ```

    // main.ts – kjør én gang ved oppstart
    import { defineDsField } from '@fristil/designsystem/field'
    import '@fristil/designsystem/field.css'
    defineDsField()

    // ContactForm.tsx
    import { useState } from 'react'

    export function ContactForm() {
      const [name, setName] = useState('')
      const [touched, setTouched] = useState(false)

      const invalid = touched && !name.trim()

      return (
        <form onSubmit={(e) => e.preventDefault()}>
          <fs-field required-marker="symbol" invalid={invalid}>
            <label>Navn</label>
            <input
              className="fs-input"
              type="text"
              name="name"
              value={name}
              onChange={(e) => setName(e.target.value)}
              onBlur={() => setTouched(true)}
            />
            <p className="fs-error-text">Navn er påkrevd.</p>
          </fs-field>
          <button className="fs-button" type="submit">Send</button>
        </form>
      )
    }
    ```

## Attributter

| Attributt | Type | Effekt |
|---|---|---|
| `invalid` | boolean | Setter `aria-invalid` og invalid state på kontroll |
| `disabled` | boolean | Setter disabled/aria-disabled på kontroll og label |
| `optional` | boolean | Setter `data-optional` på label |
| `required-marker` | `none \| symbol \| text` | Setter `data-required` på label |
| `control-id` | string | Tvinger id på kontroll |
| `described-by` | string | Legger til ekstra `aria-describedby`-id(er) |

## Når vises feilmeldingen?

Feilmeldingen vises bare når `invalid` er satt på `<fs-field>`.

Det betyr:

- `invalid` = `false` eller ikke satt: `fs-error-text` skjules.
- `invalid` = `true`: `fs-error-text` vises og kobles til feltet via `aria-describedby`.

Eksempel:

```html
<fs-field invalid>
  <label>E-post</label>
  <input class="fs-input" type="email" value="ola@" />
  <p class="fs-error-text">Skriv en gyldig e-post.</p>
</fs-field>
```

Når feltet ikke er invalid, trenger du fortsatt å ha feilmeldingselementet i markup hvis du vil bruke samme struktur senere. Komponenten skjuler det for deg til det faktisk trengs.
