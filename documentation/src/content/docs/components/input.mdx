Ren CSS på et vanlig `<input>`, så nettleserens egen validering, autofyll og tastaturhåndtering virker som før.

```js
import "@fristil/designsystem/tokens.css"
import "@fristil/designsystem/input.css"
```

## Tilstander

<Eksempel stiler={["input", "label"]} layout="stabel" maxWidth="26rem" kode={`
<label class="fs-label" for="epost">E-postadresse</label>
<input class="fs-input" id="epost" type="email" placeholder="ola&#64;eksempel.no" />

<label class="fs-label" for="bekreft">Bekreft e-postadresse</label>
<input class="fs-input" id="bekreft" type="email" data-state="success" value="ola&#64;eksempel.no" />

<label class="fs-label" for="reserve">Reserve-e-post</label>
<input class="fs-input" id="reserve" type="email" data-state="invalid" aria-invalid="true" value="ola&#64;" />

<label class="fs-label" for="registrert">Registrert e-postadresse</label>
<input class="fs-input" id="registrert" type="email" value="ola&#64;eksempel.no" disabled />
`} />

| `data-state` | Brukes til |
| --- | --- |
| *(utelatt)* | Normaltilstand |
| `invalid` | Valideringen har feilet |
| `success` | Verdien er bekreftet gyldig |

`data-state` er farge. Skjermlesere trenger `aria-invalid="true"` i tillegg — eller [Field](../field/), som setter begge.

## Dato og klokkeslett

<Eksempel stiler={["input", "label"]} layout="stabel" maxWidth="26rem" kode={`
<label class="fs-label" for="dato">Reisedato</label>
<input class="fs-input" id="dato" data-variant="date" type="date" value="2026-05-31" />

<label class="fs-label" for="tid">Avreisetidspunkt</label>
<input class="fs-input" id="tid" data-variant="time" type="time" value="14:30" />
`} />

:::caution[`data-variant` og `type` må være like]
Ikonet styres av `data-variant`, velgeren av `type`. Setter du bare den ene, får du et felt som ser ut som et datofelt, men der ingenting skjer når brukeren trykker på ikonet.

`fs.input({ type: "date" })` setter begge, og fjerner feilen helt.
:::

Bare `date`, `time` og `datetime-local` påvirker utseendet. De øvrige typene finnes for at TypeScript-hjelperen skal kunne sette `type` for deg.

## Hvilken komponent til dato?

| Situasjon | Komponent |
| --- | --- |
| Nettleserens egen datovelger holder | **Input** med `type="date"` |
| Du trenger et kalenderpanel du styrer selv | [Calendar](../calendar/) |
| Du vil ha felt, ledetekst, hjelpetekst og kalender ferdig koblet | [Date Field](../date-field/) |

## Med TypeScript

```ts
import { fs } from "@fristil/designsystem"

fs.input({ type: "date" })
// { class: "fs-input", type: "date", "data-variant": "date" }

fs.input({ state: "invalid" })
// { class: "fs-input", type: "text", "data-state": "invalid", "aria-invalid": "true" }
```

Én verdi styrer både HTML-typen og ikonvarianten, og `state` setter `aria-invalid` sammen med fargen. Begge fellene over forsvinner.

Verdier utenfra: `fs.input.isType(x)` og `fs.input.isState(x)`. Se [Typesikker bruk](../../typesikker-bruk/).

## Tilgjengelighet

- Hvert felt trenger en synlig `<label>` med `for`. `placeholder` er ingen erstatning — den forsvinner idet brukeren skriver.
- Bruk riktig `type`. Det bestemmer mobiltastaturet og hva nettleseren tilbyr av autofyll.
- Sett `autocomplete` på felt som spør om personopplysninger, for eksempel `autocomplete="email"`.
