Alle verdier i Fristil — farger, avstander, skriftstørrelser — er CSS-variabler i `tokens.css`. Det er den ene måten alt henter verdiene sine fra, enten du skriver ren CSS, bruker Tailwind eller setter stiler fra JavaScript.

```js
import "@fristil/designsystem/tokens.css"
```

```css
.min-komponent {
	color: var(--semantic-interactive-main);
	padding: var(--size-4);
	font-size: var(--font-size-m);
}
```

:::note[tokens.css redigeres ikke for hånd]
Fila er generert fra `designsystem/src/tokens/tokens.ts`. Endrer du en verdi, endrer du den der og kjører `bun --filter @fristil/designsystem generate`. Redigerer du `tokens.css` direkte, blir endringen overskrevet neste gang noen bygger.
:::

## To lag med farger

Fargene finnes i to lag, og du skal nesten alltid bruke det ytterste.

**Palett** — `--palette-{farge}-{trinn}` — er råverdiene. Seks fargeskalaer med trinn fra 5 (lysest) til 100 (mørkest).

**Semantisk** — `--semantic-{sammenheng}-{rolle}` — peker på en palettfarge og sier hva den betyr. `--semantic-interactive-main` er `--palette-azure-70` i dag, men det er en beslutning som kan endres ett sted.

Bruker du den semantiske varianten, følger komponenten din med når paletten justeres. Bruker du palettfargen direkte, gjør den ikke det.

| Gruppe | Variabler | Brukes til |
| --- | --- | --- |
| Side | `--semantic-page-background`, `--semantic-page-foreground` | Bakgrunn og tekst på en vanlig flate |
| Interaktiv | `--semantic-interactive-main`, `-background`, `-foreground` | Lenker, knapper, fokusmarkering |
| Suksess | `--semantic-success-background`, `-foreground` | Fullført, godkjent |
| Advarsel | `--semantic-warning-background`, `-foreground` | Krever oppmerksomhet |
| Fare | `--semantic-danger-background`, `-foreground` | Feil, sletting, avslag |
| Deaktivert | `--semantic-disabled-background`, `-foreground` | Kontroller som er slått av |
| Nøytral | `--semantic-neutral-background`, `-foreground` | Dempet, men lesbar informasjon |
| Skillelinjer | `--semantic-divider-30`, `--semantic-divider-100` | Rammer og streker, svak og sterk |

Paret `background` og `foreground` er laget for å brukes sammen. Bruker du dem som par, er kontrasten kontrollert mot WCAG AA av testene i designsystemet.

### Deaktivert eller nøytral?

De to parene ser nesten like ut, men kravene til dem er forskjellige, og det er derfor de er skilt.

**`disabled`** er for kontroller som er slått av. WCAG 1.4.3 unntar inaktive komponenter fra kontrastkravet, så denne er bevisst dempet — den skal signalisere «dette kan du ikke bruke».

**`neutral`** er for informasjon brukeren faktisk skal lese, men som ikke skal rope: et statusmerke som sier «Arkivert», eller dagene fra nabomåneden i kalenderen. De er dempet, men fullt klikkbare eller lesbare, og har derfor 6,7:1 i kontrast.

Regelen er enkel: er elementet slått av, bruk `disabled`. Kan brukeren lese eller trykke på det, bruk `neutral`.

## Størrelser

Én skala, `--size-*`, brukes til alt som handler om avstand og utstrekning: `padding`, `margin`, `gap`, `width`, `height`. Det finnes ingen egen `--spacing-*`-skala.

Skalaen har fire piksler som grunnenhet, som Tailwind, så `--size-4` tilsvarer `p-4`.

| Variabel | Verdi | Tailwind |
| --- | --- | --- |
| `--size-px` | 1px | — |
| `--size-0-5` | 0.125rem | `0.5` |
| `--size-1` | 0.25rem | `1` |
| `--size-2` | 0.5rem | `2` |
| `--size-3` | 0.75rem | `3` |
| `--size-4` | 1rem | `4` |
| `--size-5` | 1.25rem | `5` |
| `--size-6` | 1.5rem | `6` |
| `--size-8` | 2rem | `8` |
| `--size-10` | 2.5rem | `10` |
| `--size-12` | 3rem | `12` |
| `--size-16` | 4rem | `16` |

## Fra TypeScript

Alle variabelnavnene finnes som en typet oppslagstabell, så editoren fanger skrivefeil:

```ts
import { cssTokens, type CssToken } from "@fristil/designsystem/tokens"

const token: CssToken = "--semantic-interactive-main"
element.style.setProperty(token, "red")

cssTokens["--palette-azure-70"]
// "#1362ae"
```

`CssToken` er unionen av alle gyldige navn. Skriver du `--semantic-interactiv-main`, får du feil i editoren i stedet for en `var()` som stille faller tilbake til ingenting.

## Brekkpunkter og containere

Brekkpunkter og containerbredder er ikke CSS-variabler. De brukes når oppsettet bygges, ikke når det tegnes, og eksporteres derfor som konstanter:

```ts
import { Breakpoints, Containers } from "@fristil/designsystem/tokens"

Breakpoints.md   // "768px"
Containers.aside // "384px"
```

Brekkpunktene følger Tailwind: `sm` 640px, `md` 768px, `lg` 1024px, `xl` 1280px, `2xl` 1536px.

## Med Tailwind

`fristilPreset` kobler Tailwind-klassene til de samme variablene:

```ts
// tailwind.config.ts
import { fristilPreset } from "@fristil/designsystem/tailwind"

export default {
	presets: [fristilPreset],
}
```

Da gir `text-interactive`, `bg-danger-bg` og `border-divider` de samme verdiene som `var(--semantic-interactive-main)` og de andre. Brekkpunkter, containerbredder og hele paletten følger med.

Forhåndsinnstillingen er et tillegg, ikke et krav. Velger du den bort, skriver du `var()` i stedet — verdiene er de samme.
