Samme utseende og tilstander som [Input](../input/), på et ekte `<select>`. Da brukes nettleserens egen liste, den som allerede virker med tastatur, skjermleser og mobilens innebygde velger.

`lt` brukes på to måter, og hvilken avhenger av om du lager elementet eller finner det.

**Lager du markupen,** sprer du attributtene inn. Det er veien i React, Astro og alt annet som rendrer:

```tsx
import { lt } from "@lo-tek/interfaces/react"

<select {...lt.select({ picker: "styled" })} id="fylke" name="fylke">
  <option value="">Velg fylke</option>
  <option value="vestland">Vestland</option>
</select>
```

Importen går til `/react` her, siden blokka er JSX. Derfra heter nøklene `className` og `htmlFor`. I Astro og alt annet uten React importerer du `@lo-tek/interfaces` og får `class` og `for`.

**Står elementet der fra før,** setter du dem på det. Det er veien når du forbedrer HTML en server eller en mal har sendt:

```ts
import { lt, type FieldState } from "@lo-tek/interfaces"

const felt = document.querySelector<HTMLSelectElement>("#fylke")
if (!felt) throw new Error("fant ikke elementet")

felt.addEventListener("change", () => {
  const tilstand: FieldState = felt.value === "" ? "invalid" : "default"

  lt.setAttributes(felt, lt.select({ state: tilstand, picker: "styled" }))
})
```

`state` er samme type som i [Input](../input/) og [Textarea](../textarea/). Går feltet tilbake til `"default"`, fjerner `lt.setAttributes` både `data-state` og `aria-invalid`.

Hvert kall setter hele tilstanden. Utelater du `picker`, fjernes `data-picker` på samme måte som `data-state`, så send med de valgene feltet skal beholde.

| `data-state` | Brukes til |
| --- | --- |
| *(utelatt)* | Normaltilstand |
| `invalid` | Valideringen har feilet |

Den første `<option>` bør ha tom `value` når feltet er påkrevd. Da stopper `required` faktisk innsending til brukeren har valgt noe.

## Listen tegnet i siden

Selve listen som spretter opp er normalt et vindu fra operativsystemet, og ingen CSS når inn i den. Med `data-picker="styled"` ber feltet nettleseren tegne listen inne i siden i stedet, slik at den får systemets farger, avstander og skygge.

<Example stiler={["select", "label"]} layout="stabel" maxWidth="26rem" kode={`
<label class="lt-label" for="sak">Sakstype</label>
<select class="lt-select" data-picker="styled" id="sak" name="sak">
  <option value="">Velg sakstype</option>
  <option value="byggesak" selected>Byggesak</option>
  <option value="deling">Deling av eiendom</option>
  <option value="utslipp">Utslippstillatelse</option>
</select>
`} />

Dette er den samme `<select>`-en som før. Den sendes inn med skjemaet, leses av skjermlesere og virker med tastatur på nøyaktig samme måte, og markupen er uendret bortsett fra attributtet.

Et valg som er lengre enn feltet, brytes da over flere linjer, og feltet blir høyere. Skal det heller klippes med «…», legg `<button><selectedcontent></selectedcontent></button>` først i `<select>`-en. Nettleseren lager ikke `<selectedcontent>` selv, men fyller det med det valgte alternativet når det står der, og LO-TEK klipper det. Nettlesere uten støtte hopper over knappen.

Grupper laget med `<optgroup label="…">` får overskriften i mindre og dempet tekst, så den skiller seg fra valgene.

Støtten er ulik mellom nettleserne, og det er grunnen til at dette må slås på:

| Nettleser | Hva brukeren ser |
| --- | --- |
| Chromium og Safari som støtter `appearance: base-select` | Listen tegnes i siden, med LO-TEKs farger |
| Firefox | Nettleserens egen liste, som uten attributtet |

Det er den ene betingelsen stilarket spør om, så hver versjon som har `appearance: base-select` tegner listen i siden. LO-TEK er testet i Chromium 148 og WebKit 26.4. Firefox får altså ingen ny funksjonalitet, men heller ingenting som ser ødelagt ut. Skal alle brukere se det samme, la attributtet være.

I høykontrastmodus faller feltet tilbake til nettleserens egen liste i alle nettlesere. Systemfargene er de eneste som er garantert lesbare der.

```ts
import { lt } from "@lo-tek/interfaces"

lt.select({ picker: "styled" })
// { class: "lt-select", "data-picker": "styled" }
```

## Klasser du kan style

| Klasse | Hva det er |
| --- | --- |
| `.lt-select` | Nedtrekkslisten. Tilstanden kommer fra `data-state`, listen fra `data-picker`. |

| Variabel | Standard | Gjelder |
| --- | --- | --- |
| `--lt-select-width` | `100%` | Bredden på feltet |
| `--lt-select-padding` | `var(--lt-spacing-2) var(--lt-spacing-3)` | Luften i feltet |
| `--lt-select-radius` | `var(--lt-spacing-1)` | Feltet, og listen som tegnes i siden |
| `--lt-select-option-padding` | `var(--lt-spacing-2) var(--lt-spacing-3)` | Ett valg i listen som tegnes i siden |
| `--lt-select-viewport-margin` | `var(--lt-spacing-2)` | Luft mellom listen og kanten av vinduet |

Pilen er to gradienter i bakgrunnen, tegnet i `--lt-color-neutral-text-subtle`, så den snur med temaet. Skal den bort, sett `background-image: none`. Med `data-picker="styled"` tegner nettleseren pilen selv, og den styles med `::picker-icon`.

I standardutseendet står plassen til pilen ved enden av feltet fast, siden pilen er tegnet et fast stykke fra kanten, og `--lt-select-padding` gjelder de tre andre sidene. Med `data-picker="styled"` tar pilen sin egen plass, og variabelen gjelder alle fire.

Et kompakt felt, som «Antall per side», blir så bredt som innholdet med `--lt-select-width: auto`. Skal ledeteksten stå ved siden av feltet, er det oppsettet rundt dem som avgjør det, ikke LO-TEK. `.lt-label` er en blokk, og en rad med `display: flex` rundt de to legger dem på linje.

Se [Tilpasning](../../customising/) for hvordan variablene og laget virker.

## Tilgjengelighet

- En `<option>` som sier «Velg fylke» er en ledetekst i forkledning, ikke en erstatning for `<label>`.
- Har listen flere enn rundt sju valg som hører logisk sammen, grupper dem med `<optgroup label="…">`.
- Ikke send skjemaet automatisk ved endring. Tastaturbrukere blar gjennom valgene med piltastene og ville sendt skjemaet på det første de passerer.
- Trenger du søk, flervalg eller ikoner i listen, er `<select>` feil verktøy. Bygg det som en frittstående komponent framfor å style om dette elementet.
