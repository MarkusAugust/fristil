## Installer

```bash
npm install @fristil/designsystem
```

Ingen påkrevde avhengigheter. `lit` trengs bare til ramme- og frittstående komponenter, `tailwindcss` bare til forhåndsinnstillingen. Begge er valgfrie `peerDependencies`.

## Importer tokens

`tokens.css` definerer alle CSS-variablene. Alle andre stilark bygger på den, så den lastes først.

<Tabs>
  <TabItem label="Med byggverktøy">
    ```js
    // main.js eller main.ts, øverst
    import "@fristil/designsystem/tokens.css"
    import "@fristil/designsystem/button.css"
    ```
  </TabItem>
  <TabItem label="Uten byggverktøy">
    ```html
    <head>
      <link rel="stylesheet" href="/node_modules/@fristil/designsystem/src/tokens/tokens.css" />
      <link rel="stylesheet" href="/node_modules/@fristil/designsystem/src/components/css/button/button.css" />
    </head>
    ```

    Serverer du filene fra en CDN som støtter npm-pakker, bruker du stien `@fristil/designsystem/tokens.css` direkte.
  </TabItem>
</Tabs>

Importer bare stilarkene du bruker. Det finnes ingen samlet CSS-fil, så en side med bare knapper laster ikke CSS for en datovelger.

Med `tokens.css` og `button.css` importert:

Ingen registrering, ingen oppstartskode. CSS-komponentene er bare klasser.

## Registrer web components

Ramme- og frittstående komponenter er egendefinerte elementer, og må registreres én gang når appen starter:

```ts
// main.ts, kjøres én gang
import "@fristil/designsystem/tokens.css"
import "@fristil/designsystem/field.css"
import { defineFsField } from "@fristil/designsystem/field"

defineFsField()
```

Flere kall er ufarlige, for funksjonen sjekker selv om elementet er registrert.

```html
<fs-field required-marker="symbol">
  <label>Fullt navn</label>
  <input class="fs-input" type="text" name="navn" required />
</fs-field>
```

Får du en tom side, har `define`-funksjonen nesten alltid ikke kjørt.

## Inngangspunkter

**Stilark**

| Import | Innhold |
| --- | --- |
| `@fristil/designsystem/tokens.css` | Alle CSS-variabler. Kreves av alt annet. |
| `@fristil/designsystem/utilities.css` | `.link` og `.srOnly` |
| `@fristil/designsystem/button.css` | [Button](../components/button/) |
| `@fristil/designsystem/link.css` | [Link](../components/link/) |
| `@fristil/designsystem/badge.css` | [Badge](../components/badge/) |
| `@fristil/designsystem/label.css` | [Label](../components/label/) |
| `@fristil/designsystem/input.css` | [Input](../components/input/) |
| `@fristil/designsystem/textarea.css` | [Textarea](../components/textarea/) |
| `@fristil/designsystem/select.css` | [Select](../components/select/) |
| `@fristil/designsystem/help-text.css` | [Help Text](../components/help-text/) |
| `@fristil/designsystem/error-text.css` | [Error Text](../components/error-text/) |
| `@fristil/designsystem/field.css` | [Field](../components/field/), med ledetekst, felt og tekster samlet |
| `@fristil/designsystem/date-field.css` | [Date Field](../components/date-field/) |

`field.css` og `date-field.css` samler stilene de trenger.

Web-komponentene krever ikke alle et stilark. `<fs-calendar>` bruker Shadow DOM og tar med stilene sine; `<fs-field>` og `<fs-date-field>` kjører i vanlig DOM, der barna er dine egne elementer med systemets klasser, og klassene må lastes på siden. Se [Introduksjon](../introduksjon/#shadow-dom).

**JavaScript og TypeScript**

Hele komponent-API-et ligger i ett navnerom:

```ts
import { fs } from "@fristil/designsystem"

fs.button({ variant: "secondary" })
fs.input({ type: "email", state: "invalid" })
fs.badge({ color: "success" })
```

Skriv `fs.` i editoren, så ser du hva som finnes. Bruker du React, importer fra `@fristil/designsystem/react`. Kallene er de samme, men returverdien bruker `className` og `htmlFor`. Se [Typesikker bruk](../typesikker-bruk/).

| Import | Innhold |
| --- | --- |
| `@fristil/designsystem` | `fs` med alle komponentene, alle typene, og web component-registreringene |
| `@fristil/designsystem/react` | Samme `fs`, men med `className` og `htmlFor` |
| `@fristil/designsystem/react-jsx` | Typer for `<fs-field>`, `<fs-calendar>` og `<fs-date-field>` i JSX |
| `@fristil/designsystem/dom` | `setAttributes`: bruker et attributtsett på et element uten JSX |
| `@fristil/designsystem/field` | `defineFsField`, klassen `FsField` |
| `@fristil/designsystem/calendar` | `defineFsCalendar`, klassen `FsCalendar` |
| `@fristil/designsystem/date-field` | `defineFsDateField`, klassen `FsDateField` |
| `@fristil/designsystem/field-core` | `computeFieldAttributes`: det `fs.field` og `<fs-field>` deler |
| `@fristil/designsystem/tokens` | `cssTokens`, `CssToken`, `Breakpoints`, `Containers` |
| `@fristil/designsystem/tailwind` | `fristilPreset` |

Hver komponent finnes også som eget inngangspunkt (`@fristil/designsystem/button`, `/badge`, `/link` og så videre) med en funksjon som heter det samme som komponenten.

`fs` er valgfritt. `class="fs-button" data-variant="secondary"` for hånd gir samme resultat; funksjonene finnes for å fange skrivefeil.
