LO-TEK er et designsystem som ikke krever et bestemt rammeverk. Komponentene er CSS-klasser og web components, altså ting nettleseren allerede forstår. Bruker teamet ditt React, Astro, Datastar eller ingenting i det hele tatt, er det samme system og samme API.

Et designsystem bundet til ett rammeverk må skrives om når rammeverket byttes ut. Nettleserens egne API-er byttes ikke ut.

## Tre kategorier

Komponentene er delt i tre: de som bare er CSS, de som fester oppførsel på HTML du skriver, og de som lager innholdet sitt selv.

### css

En CSS-klasse på et vanlig HTML-element. Ingen JavaScript lastes.

```html
<button class="lt-button" data-variant="secondary">Lagre utkast</button>
```

Varianter styres med `data-`-attributter. Dette er den største gruppen, og dekker knapper, lenker, merker, skjemafelt, tabeller, kort, varsler og typografi. Felles for dem er at utfordringen er hvordan de ser ut, ikke hva de gjør.

### ramme

En web component du legger dine egne HTML-elementer inn i. Den lager ingen markup selv, men setter attributtene som kobler dem sammen.

```html
<lt-field>
  <label class="lt-label" for="epost" data-required="symbol">E-postadresse</label>
  <input class="lt-input" id="epost" type="email" value="ola@" />
  <p class="lt-help-text">Vi sender kvittering til denne adressen.</p>
  <p class="lt-error-text">Skriv en e-postadresse med krøllalfa.</p>
</lt-field>
```

`for` og `id` står i markupen, som HTML krever for at feltet skal ha et navn uten JavaScript. Resten av koblingen, `aria-describedby` og `aria-invalid`, skriver serveren med `lt.field()`. Komponenten finnes for servere som ikke kan kalle den, og regner feltet som ugyldig fordi feilmeldingen synes. Elementene blir liggende i vanlig DOM, så `FormData`, testverktøy og skjemabiblioteker finner dem som før.

### frittstående

En web component som lager alt innholdet sitt selv, fordi det ikke finnes noe for serveren å sende.

```html
<lt-connection-status class="lt-connection-status" data-ignore-morph></lt-connection-status>
```

Kategorien er et unntak med et vilkår, ikke en tredje likeverdig vei. Den gjelder bare flater som oppstår som følge av noe på klienten, og som ikke bærer en verdi inn i en innsending. Det er én av dem: [`<lt-connection-status>`](../components/connection-status/), der serveren per definisjon ikke kan melde fra om at den er utilgjengelig. I tillegg står [`<lt-toast>`](../components/toast/), som er et imperativt API du kaller framfor å skrive.

## Hvorfor tre kategorier

Fordi problemene er ulike. En knapp trenger bare en stil. Et skjemafelt trenger at fire elementer peker på hverandre, og markupen må stå i HTML-en serveren sender, ellers finnes ikke feltet før skriptet har kjørt. En beskjed om at forbindelsen er borte, kan derimot ikke komme fra serveren som er borte.

Vilkåret som avgjør hvor en komponent hører hjemme:

> Bærer den en verdi inn i en innsending, eller har den innhold serveren må sende, kan den ikke lage sin egen markup.

Delingen gjør også at du laster det komponenten trenger og ikke mer: en knapp er null JavaScript.

## To lag: markup og oppførsel

Ingen `ramme`-komponent lager sitt eget innhold i DOM-en. Den som lager markupen beholder den, og komponenten fester bare oppførsel oppå. Det gjelder like mye i en React-app som rendrer alt i nettleseren, i en server-rendret app med hydrering, og i en Datastar-app der serveren sender HTML hele veien. Hele begrunnelsen, og svaret på når du bruker byggefunksjonen framfor elementet, står i [Markup og oppførsel](../markup-and-behaviour/).

Ingen komponent bruker shadow DOM. Alle elementene står i vanlig DOM, og CSS-en din når fram overalt.

| Komponent | Kategori | Stilark |
| --- | --- | --- |
| `<lt-field>` | ramme | `field.css` |
| `<lt-tabs>` | ramme | `tabs.css` |
| `<lt-error-summary>` | ramme | `error-summary.css` |
| `<lt-popover>` | ramme | `popover.css` |
| `<lt-suggestion>` | ramme | `suggestion.css` |
| `<lt-dialog>` | ramme | `dialog.css` |
| `<lt-toast>` | frittstående | `toast.css` |
| `<lt-session-timeout>` | ramme | `session-timeout.css` |
| `<lt-connection-status>` | frittstående | `connection-status.css` |

## Design tokens

Alle farger, størrelser og skriftstørrelser er CSS-variabler i `tokens.css`, og fungerer i all CSS:

```css
.min-komponent {
	color: var(--lt-color-accent-fill);
	padding: var(--lt-spacing-4);
	font-size: var(--lt-font-size-m);
}
```

De samme verdiene finnes som TypeScript-konstanter og som et Tailwind-tema. Se [Design tokens](../design-tokens/).

## Tailwind

LO-TEK forutsetter ikke Tailwind, men står ikke i veien. La Tailwind styre oppsettet og LO-TEK styre komponentene:

```html
<section class="mx-auto max-w-3xl p-6">
  <h2 class="mb-4 text-2xl font-bold">Handlinger</h2>
  <div class="flex flex-wrap gap-3">
    <button class="lt-button">Send søknad</button>
    <button class="lt-button" data-variant="secondary">Lagre utkast</button>
  </div>
</section>
```

Skal Tailwind-klassene bruke LO-TEKs verdier, importer `@lo-tek/interfaces/tailwind.css`. Det er en vanlig CSS-fil, så pakken har ingen avhengighet til Tailwind, og din versjon er den eneste i bildet. Se [Tailwind](../tailwind/).
