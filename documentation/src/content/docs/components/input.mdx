Ren CSS på et vanlig `<input>`, så nettleserens egen validering, autofyll og tastaturhåndtering virker som før.

`lt` brukes på to måter, og hvilken avhenger av om du lager elementet eller finner det.

**Lager du markupen,** sprer du attributtene inn. Det er veien i React, Astro og alt annet som rendrer:

```tsx
import { lt } from "@lo-tek/interfaces/react"

<input {...lt.input({ type: "email", state: "invalid" })} id="epost" />
```

Importen går til `/react` her, siden blokka er JSX. Derfra heter nøklene `className` og `htmlFor`. I Astro og alt annet uten React importerer du `@lo-tek/interfaces` og får `class` og `for`.

**Står elementet der fra før,** setter du dem på det. Det er veien når du forbedrer HTML en server eller en mal har sendt:

```ts
import { lt, type FieldState } from "@lo-tek/interfaces"

const felt = document.querySelector<HTMLInputElement>("#epost")
if (!felt) throw new Error("fant ikke feltet")

lt.setAttributes(felt, lt.input({ type: "email" }))
```

`type` setter både HTML-typen og ikonvarianten, så de kan ikke komme i utakt. Med `lt.input()` er den fella ikke mulig å gå i: en verdi som ikke finnes, er en typefeil.

Ved validering kaller du den på nytt med ny tilstand:

```ts
felt.addEventListener("blur", () => {
  const tilstand: FieldState = felt.validity.valid ? "default" : "invalid"

  lt.setAttributes(felt, lt.input({ type: "email", state: tilstand }))
})
```

`state: "invalid"` setter både `data-state` for fargen og `aria-invalid` for skjermleseren. Går feltet tilbake til `"default"`, fjerner `lt.setAttributes` begge. Uten det ville feltet blitt stående rødt etter at feilen var rettet.

Verdier utenfra: `lt.input.isType(x)` og `lt.input.isState(x)`. Se [Typesikker bruk](../../type-safe-use/).

| `data-state` | Brukes til |
| --- | --- |
| *(utelatt)* | Normaltilstand |
| `invalid` | Valideringen har feilet |
| `success` | Verdien er bekreftet gyldig |

`data-state` er farge. Skjermlesere trenger `aria-invalid="true"` i tillegg, eller [Field](../field/), som setter begge.

## Dato og klokkeslett

<Example stiler={["input", "label"]} layout="stabel" maxWidth="26rem" kode={`
<label class="lt-label" for="dato">Reisedato</label>
<input class="lt-input" id="dato" data-variant="date" type="date" value="2026-05-31" />

<label class="lt-label" for="tid">Avreisetidspunkt</label>
<input class="lt-input" id="tid" data-variant="time" type="time" value="14:30" />
`} />

:::caution[`data-variant` og `type` må være like]
Ikonet styres av `data-variant`, velgeren av `type`. Setter du bare `data-variant`, får du et felt som ser ut som et datofelt, men der ingenting skjer når brukeren trykker på ikonet. Setter du bare `type`, står nettleserens egen knapp igjen, og den virker.

`lt.input({ type: "date" })` setter begge, og fjerner feilen helt.
:::

Bare `date`, `time` og `datetime-local` påvirker utseendet. De øvrige typene finnes for at TypeScript-hjelperen skal kunne sette `type` for deg.

## Hvilken datokomponent?

| Situasjon | Komponent |
| --- | --- |
| Nettleserens egen datovelger holder | **Input** med `type="date"` |
| Du skal be om en dato | [Dato i et skjema](../../patterns/date/) |

## Classes you can style

| Klasse | Hva det er |
| --- | --- |
| `.lt-input` | Feltet. Tilstanden kommer fra `data-state`, ikonet fra `data-variant`. |

| Variabel | Standard |
| --- | --- |
| `--lt-input-width` | `100%` |
| `--lt-input-padding` | `var(--lt-spacing-2) var(--lt-spacing-3)` |
| `--lt-input-radius` | `var(--lt-spacing-1)` |

Et eksempel. Et skjema som skal fylles ut på mobil tåler større treffflater, og huset ditt vil kanskje ha rette hjørner:

<Example stiler={["input", "label"]} layout="stabel" maxWidth="26rem" egenCss={`
.romslig-skjema {
	--lt-input-padding: var(--lt-spacing-3) var(--lt-spacing-4);
	--lt-input-radius: 0;
}
`} kode={`
<label class="lt-label" for="standard">Fødselsnummer</label>
<input class="lt-input" id="standard" type="text" />

<div class="romslig-skjema">
  <label class="lt-label" for="romslig">Fødselsnummer</label>
  <input class="lt-input" id="romslig" type="text" />
</div>
`} />

Variabelen står på beholderen, ikke på feltet, så den gjelder hvert felt i skjemaet uten at du rører noen av dem.

Se [Tilpasning](../../customising/) for hvordan variablene og laget virker.

## Accessibility

- Hvert felt trenger en synlig `<label>` med `for`. `placeholder` er ingen erstatning, siden den forsvinner idet brukeren skriver.
- Bruk riktig `type`. Det bestemmer mobiltastaturet og hva nettleseren tilbyr av autofyll.
- Sett `autocomplete` på felt som spør om personopplysninger, for eksempel `autocomplete="email"`.
