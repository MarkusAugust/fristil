`fs-textarea` gir `<textarea>` samme utseende og tilstander som [Input](../input/). Bruk det når svaret kan bli lengre enn én linje — en begrunnelse, en melding, en beskrivelse.

## Importer

```js
import "@fristil/designsystem/tokens.css"
import "@fristil/designsystem/textarea.css"
```

| `data-state` | Når du bruker den |
| --- | --- |
| *(utelatt)* | Normaltilstand |
| `invalid` | Valideringen har feilet. Sett `aria-invalid="true"` i tillegg. |
| `success` | Innholdet er bekreftet gyldig. |

Sett `rows` til omtrent så mye tekst du faktisk forventer. Et felt med tre rader signaliserer noe annet til brukeren enn et felt med ti.

## TypeScript

```ts
import { getTextareaStyleAttributes } from "@fristil/designsystem/textarea"

getTextareaStyleAttributes("success")
// { class: "fs-textarea", "data-state": "success" }

getTextareaStyleAttributes()
// { class: "fs-textarea" }
```

Verdier som kommer utenfra, validerer du først:

```ts
import {
	getTextareaStyleAttributes,
	isTextareaState,
} from "@fristil/designsystem/textarea"

const fraServer = String(svar.state)
const tilstand = isTextareaState(fraServer) ? fraServer : "default"

getTextareaStyleAttributes(tilstand)
```

## Tilgjengelighet

- Hvert felt trenger en synlig `<label>` med `for` som peker på `id`-en.
- Har feltet en øvre grense, si det før brukeren skriver — i hjelpeteksten, ikke bare i en teller. `maxlength` alene hindrer innskriving uten å forklare hvorfor.
- Bruker du en tegnteller som oppdateres mens brukeren skriver, legg den i et element med `aria-live="polite"`, og la den bare melde fra ved runde tall eller når grensen nærmer seg. Ellers avbryter den opplesingen for hvert tastetrykk.
- Ikke slå av muligheten til å endre størrelsen på feltet med `resize: none`. Det er ofte den eneste måten brukeren kan få oversikt over lang tekst.
