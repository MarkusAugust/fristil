`fs-label` gir `<label>` riktig typografi og en fast måte å markere påkrevde og valgfrie felt på, via dataattributter.

Setter du opp et helt felt med ledetekst, hjelpetekst og feilmelding, er det som regel enklere å bruke [Field](../field/). Den setter `for`, `id` og `aria-describedby` for deg. Denne siden handler om selve ledeteksten.

## Importer

```js
import "@fristil/designsystem/tokens.css"
import "@fristil/designsystem/label.css"
```

| Attributt | Hva det gjør |
| --- | --- |
| *(utelatt)* | Vanlig ledetekst |
| `data-required="symbol"` | Legger til ` *` i farefargen |
| `data-required="text"` | Legger til ` (påkrevd)` i farefargen |
| `data-optional=""` | Legger til ` (valgfri)` i dempet farge |
| `aria-disabled="true"` | Demper tekstfargen |

Velg én av `data-required` og `data-optional` og hold deg til den gjennom hele skjemaet. Markerer du både det påkrevde og det valgfrie, må brukeren lese begge deler for å finne ut hva som gjelder.

## Sammen med et felt

Ledeteksten skal peke på feltet sitt med `for`, som må matche `id` på feltet. Uten den koblingen leser ikke skjermleseren opp ledeteksten når feltet får fokus, og et klikk på teksten flytter ikke fokus til feltet.

<Tabs>
  <TabItem label="Eksempel">

      <label class="fs-label" data-required="symbol" for="demo-epost">E-postadresse</label>
      <input class="fs-input" id="demo-epost" type="email" required placeholder="ola@eksempel.no" />
      <p class="fs-help-text">Vi bruker adressen til å sende kvittering.</p>
    </Preview>
  </TabItem>
  <TabItem label="Kode">
    ```html
    <label class="fs-label" data-required="symbol" for="epost">E-postadresse</label>
    <input class="fs-input" id="epost" type="email" required aria-describedby="epost-hjelp" />
    <p class="fs-help-text" id="epost-hjelp">Vi bruker adressen til å sende kvittering.</p>
    ```
  </TabItem>
</Tabs>

Dette er nøyaktig den koblingen [Field](../field/) gjør automatisk. Skriver du den for hånd, må du holde styr på `id`-ene selv.

## TypeScript

```ts
import { fs } from "@fristil/designsystem"

fs.label({ required: "text" })
// { class: "fs-label", "data-required": "text" }

fs.label({ optional: true })
// { class: "fs-label", "data-optional": "" }
```

Funksjonen returnerer bare Fristils egne attributter — `for` og `id` eier du selv:

```tsx
<label {...fs.label({ required: "symbol" })} htmlFor="epost">
  E-postadresse
</label>
```

Kommer markeringen utenfra, valider den først:

```ts
const required = fs.label.isMarker(svar.marker) ? svar.marker : undefined

fs.label({ required })
```

Setter du opp et helt felt, gjør [`fs.field`](../../typesikker-bruk/#fsfield-kobler-et-helt-felt) både dette og koblingen til kontrollen i én operasjon.

## I React

Samme funksjon, spredt inn i et vanlig `<label>`. Ingen Fristil-spesifikk komponent trengs:

```tsx
import { fs } from "@fristil/designsystem/react"
import type { RequiredMarker } from "@fristil/designsystem"

type Props = {
	htmlFor: string
	required?: RequiredMarker
	optional?: boolean
	children: React.ReactNode
}

export function Ledetekst({ htmlFor, required, optional, children }: Props) {
	return (
		<label {...fs.label({ required, optional })} htmlFor={htmlFor}>
			{children}
		</label>
	)
}
```

## Tilgjengelighet

- `for` må alltid peke på `id`-en til feltet. Det er koblingen som gjør at klikk på ledeteksten flytter fokus, og at skjermleseren leser riktig tekst.
- `data-required` er bare visuelt. Skjermleseren får ikke vite at feltet er påkrevd med mindre du også setter `required` eller `aria-required="true"` på selve feltet.
- Stjernen legges til med `::after` og leses ikke opp. Det er meningen — `required` på feltet formidler det samme, og en opplest «stjerne» ved hvert felt blir bare støy.
- Skjul aldri ledeteksten helt. Trenger du den visuelt borte, bruk `.srOnly` fra `utilities.css` framfor `placeholder`, som forsvinner så fort brukeren begynner å skrive.
