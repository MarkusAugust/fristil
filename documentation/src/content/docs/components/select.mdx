`fs-select` gir `<select>` samme utseende og tilstander som [Input](../input/). Det er et ekte select-element, så nettleserens egen nedtrekksliste brukes — den som allerede fungerer med tastatur, skjermleser og mobilens innebygde velger.

## Importer

```js
import "@fristil/designsystem/tokens.css"
import "@fristil/designsystem/select.css"
```

| `data-state` | Når du bruker den |
| --- | --- |
| *(utelatt)* | Normaltilstand |
| `invalid` | Valideringen har feilet. Sett `aria-invalid="true"` i tillegg. |
| `success` | Valget er bekreftet gyldig. Bruk sparsomt — en grønn ramme på hvert felt blir støy. |

Den første `<option>` bør ha tom `value` når feltet er påkrevd. Da vil `required` faktisk stoppe innsending til brukeren har valgt noe.

## TypeScript

```ts
import { fs } from "@fristil/designsystem"

fs.select({ state: "invalid" })
// { class: "fs-select", "data-state": "invalid", "aria-invalid": "true" }

fs.select()
// { class: "fs-select" }
```

`state` er den samme typen som i [Input](../input/) og [Textarea](../textarea/), så en verdi kan sendes mellom dem uten konvertering.

Verdier som kommer fra et API eller en URL, validerer du først:

```ts
const state = fs.select.isState(svar.state) ? svar.state : "default"

fs.select({ state })
```

## Tilgjengelighet

- Hvert felt trenger en synlig `<label>` med `for`. En `<option>` som sier «Velg fylke» er en ledetekst i forkledning, ikke en erstatning.
- Har listen flere enn rundt sju valg som hører logisk sammen, grupper dem med `<optgroup label="...">`.
- Ikke send skjemaet automatisk når brukeren endrer valget. Tastaturbrukere blar gjennom valgene med piltastene, og ville da sendt skjemaet på det første alternativet de passerer.
- Trenger du søk, flervalg med merkelapper eller egne ikoner i listen, er `<select>` feil verktøy. Bygg det som en egen `sammensatt`-komponent i stedet for å style om dette elementet.
