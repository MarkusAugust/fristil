`<fs-field>` er en **rammekomponent**. Du legger inn dine egne `<label>`, `<input>` og tekster som vanlig HTML, og komponenten setter `for`, `id`, `aria-describedby` og `aria-invalid` for deg.

Den lager ingen markup selv og bruker ikke Shadow DOM. Elementene dine blir liggende i vanlig DOM, der skjemabiblioteker, testverktøy og `FormData` finner dem.

## Hvorfor det er verdt en web component

Et felt med ledetekst, hjelpetekst og feilmelding krever fem koblinger som alle må stemme samtidig:

```html
<label for="epost">E-postadresse</label>
<input id="epost" aria-invalid="true" aria-describedby="epost-hjelp epost-feil" />
<p id="epost-hjelp">Vi sender kvittering hit.</p>
<p id="epost-feil">Skriv en gyldig e-postadresse.</p>
```

Hver `id` må være unik på siden, `aria-describedby` må peke på begge tekstene, og `aria-invalid` må skrus av og på i takt med valideringen. Det er fem steder å gjøre feil per felt, ganget med antall felt i skjemaet.

`<fs-field>` gjør den koblingen én gang, i systemet, i stedet for i hver app.

## Kom i gang

```ts
// main.ts – kjøres én gang når appen starter
import { defineFsField } from "@fristil/designsystem/field"
import "@fristil/designsystem/field.css"

defineFsField()
```

`defineFsField()` registrerer `<fs-field>` i nettleseren. Før registreringen er taggen bare en ukjent HTML-tag uten oppførsel; etter den er den en web component. Kall den én gang ved oppstart — flere kall er ufarlige, for funksjonen sjekker selv om elementet allerede finnes.

`field.css` inneholder stilene for ledetekst, felt, hjelpetekst og feilmelding samlet, så du slipper å importere dem hver for seg.

Deretter skriver du HTML-en som vanlig, med `<fs-field>` rundt:

Legg merke til at `<label>` ikke har `for`, og at tekstene ikke har `id`. Det er med vilje — komponenten fyller ut begge deler når siden lastes.

## Minste mulige bruk

```html
<fs-field>
  <label>Fullt navn</label>
  <input class="fs-input" type="text" />
</fs-field>
```

Dette alene gir deg en fungerende kobling mellom ledetekst og felt. Klikk på teksten flytter fokus til feltet, og skjermleseren leser riktig ledetekst.

## Hva komponenten gjør

Den leter etter et `<label>` og én kontroll (`input`, `select` eller `textarea`) blant barna sine, og gjør så følgende hver gang innholdet eller attributtene endrer seg:

1. Gir kontrollen en `id` hvis den mangler, og setter `label[for]` til den.
2. Gir hjelpetekst og feilmelding `id` ved behov.
3. Setter `aria-describedby` på kontrollen, med begge tekstene når begge finnes.
4. Setter `aria-invalid="true"` på kontrollen når `invalid` er satt.
5. Setter `data-required` eller `data-optional` på ledeteksten ut fra attributtene på `<fs-field>`.
6. Viser eller skjuler `fs-error-text` ut fra `invalid`.

Punkt 6 betyr at feilmeldingen kan ligge i markupen hele tiden. Den er skjult til feltet faktisk er ugyldig, så du slipper å legge den til og fjerne den fra DOM-en selv.

## Attributter

| Attributt | Type | Hva det gjør |
| --- | --- | --- |
| `invalid` | boolsk | Setter `aria-invalid` på kontrollen og viser feilmeldingen |
| `disabled` | boolsk | Setter `disabled` på kontrollen og demper ledeteksten |
| `optional` | boolsk | Setter `data-optional` på ledeteksten |
| `required-marker` | `none \| symbol \| text` | Setter `data-required` på ledeteksten |
| `control-id` | streng | Bestemmer `id`-en på kontrollen i stedet for å la komponenten lage en |
| `described-by` | streng | Legger til ekstra `id`-er i `aria-describedby`, i tillegg til hjelp og feil |

`required-marker` er bare visuelt. Skal skjemaet faktisk kreve feltet, må `required` stå på selve `<input>`-elementet.

    ```html
      <fs-field id="navn-felt" required-marker="symbol">
        <label>Fullt navn</label>

    <script type="module">
      import { defineFsField } from "@fristil/designsystem/field"
      defineFsField()

      const skjema = document.getElementById("kontaktskjema")
      const navnFelt = document.getElementById("navn-felt")
      const navnInput = navnFelt.querySelector("input")

      skjema.addEventListener("submit", (hendelse) => {
        hendelse.preventDefault()

        const tomt = navnInput.value.trim() === ""
        navnFelt.toggleAttribute("invalid", tomt)

        if (tomt) {
          navnInput.focus()
          return
        }

        const data = new FormData(skjema)
        console.log(Object.fromEntries(data))
      })
    </script>
    ```

    `new FormData(skjema)` plukker opp feltet uten videre. Det er hele poenget med at komponenten holder seg i vanlig DOM.

    ```tsx
    // Kontaktskjema.tsx
    import { useState } from "react"

    export function Kontaktskjema() {
      const [navn, setNavn] = useState("")
      const [berørt, setBerørt] = useState(false)

      const ugyldig = berørt && navn.trim() === ""

      return (
        <form onSubmit={(e) => e.preventDefault()}>
          <fs-field required-marker="symbol" invalid={ugyldig ? "" : undefined}>
            <label>Fullt navn</label>
            <input
              className="fs-input"
              type="text"
              name="navn"
              value={navn}
              onChange={(e) => setNavn(e.target.value)}
              onBlur={() => setBerørt(true)}
            />
            <p className="fs-error-text">Fyll inn navnet ditt.</p>
          </fs-field>

          <button className="fs-button" type="submit">Send</button>
        </form>
      )
    }
    ```

    Legg merke til `invalid={ugyldig ? "" : undefined}` framfor `invalid={ugyldig}`. Boolske HTML-attributter er sanne så lenge de finnes, uansett verdi — `invalid="false"` ville altså gjort feltet ugyldig. Med `undefined` fjerner React attributtet helt.

    ```vue
    const ugyldig = computed(() => berørt.value && navn.value.trim() === "")

      <form @submit.prevent>
        <fs-field required-marker="symbol" :invalid="ugyldig || null">
          <label>Fullt navn</label>
          <input
            class="fs-input"
            type="text"
            name="navn"
            v-model="navn"
            @blur="berørt = true"
          />
          <p class="fs-error-text">Fyll inn navnet ditt.</p>
        </fs-field>

        <button class="fs-button" type="submit">Send</button>
      </form>
    </template>
    ```

## Tilgjengelighet

- Komponenten gjør koblingen, ikke innholdet. Du må fortsatt skrive en ledetekst som forklarer hva feltet spør om, og en feilmelding som sier hva brukeren skal gjøre.
- `required-marker` er visuelt. Sett `required` på `<input>` i tillegg, ellers vet ikke skjermleseren at feltet må fylles ut.
- Sett `invalid` når brukeren har forlatt feltet, ikke for hvert tastetrykk. Feilmeldingen blir lest opp hver gang den dukker opp.
- Ikke legg flere kontroller inn i samme `<fs-field>`. Komponenten kobler seg til den første den finner, og resten blir stående uten kobling. Grupper av felt hører hjemme i en `<fieldset>` med `<legend>`.
