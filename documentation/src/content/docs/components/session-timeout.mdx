Dette er tingen hver store organisasjon bygger selv, og gjør feil. Enten kommer det ingen advarsel, og brukeren mister et halvutfylt søknadsskjema. Eller dialogen stjeler fokus midt i en setning. Eller skjermleseren leser nedtellingen hvert eneste sekund.

Du skriver dialogen og teksten selv, på språket appen bruker. Komponenten teller aktivitet, åpner dialogen, fyller inn tallet og leser opp nedtellingen.

```ts
// main.ts, kjøres én gang når appen starter
import { defineFsSessionTimeout } from "@fristil/designsystem/session-timeout"
import "@fristil/designsystem/tokens.css"
import "@fristil/designsystem/session-timeout.css"

defineFsSessionTimeout()
```

    ```tsx
    import { useEffect, useId, useRef } from "react"
    import { fs } from "@fristil/designsystem/react"
    import { defineFsSessionTimeout } from "@fristil/designsystem/session-timeout"
    import "@fristil/designsystem/tokens.css"

    defineFsSessionTimeout()

    export function Okt() {
      const ref = useRef<HTMLElement>(null)
      const okt = fs.sessionTimeout({ titleId: useId(), warnAt: 1500, expiresAt: 1800 })

      useEffect(() => {
        const element = ref.current
        if (!element) return

        const forleng = () => fetch("/api/forleng-okt", { method: "POST" })

        element.addEventListener("session-extend", forleng)
        element.addEventListener("session-expired", utlopt)
        return () => {
          element.removeEventListener("session-extend", forleng)
          element.removeEventListener("session-expired", utlopt)
        }
      }, [])

      return (
        <fs-session-timeout ref={ref} {...okt.host}>
          <dialog {...okt.dialog}>
            <h2 {...okt.title}>Du blir snart logget ut</h2>
            <p {...okt.text}>
              Vi logger deg ut om <span {...okt.count} /> for å beskytte opplysningene dine.
            </p>
            <span {...okt.live} />
            <form {...okt.actions}>
              <button {...okt.extend}>Fortsett å være innlogget</button>
              <button {...okt.logout}>Logg ut nå</button>
            </form>
          </dialog>
        </fs-session-timeout>
      )
    }
    ```

## Hvorfor du skriver dialogen selv

Teksten i varselet hører til appen. Den skal stå på språket appen bruker, med de ordene appen bruker om innlogging, og komme fra det oversettelsesoppsettet appen alt har. Lå teksten i komponenten, kunne den ikke oversettes i det hele tatt. Se [Oversettelse](/oversettelse/).

Komponenten finner delene på det som uansett må stå der:

| Del | Kjennes igjen på |
| --- | --- |
| Dialogen | Den første `<dialog>` inne i elementet |
| Tallet | `.fs-session-timeout__count`. Står tomt, og komponenten fyller det inn |
| Opplesningen | `[role=status]`. Står tom, og komponenten fyller den inn |
| Knappene | Knapper i et `<form method="dialog">` |

Knappene er vanlige knapper. Nettleseren lukker dialogen og setter `returnValue` til knappens `value`, uten skript. `value="logout"` logger ut. Alt annet, Escape og knappen med `value="extend"` medregnet, betyr at brukeren vil fortsette.

Mangler klassen `fs-session-timeout__dialog`, `role="alertdialog"` eller et navn på dialogen, fyller komponenten dem inn. Navnet kommer fra den første overskriften, som får en id hvis den ikke har en. Det den som rendrer har skrevet, blir stående.

Nedtellingen er klientens klokke, og endrer seg ut fra når brukeren sist rørte tastaturet. Derfor setter byggefunksjonen `data-ignore-morph`, så en patch fra serveren lar varselet være. Tar en patch likevel `open` fra en dialog som står i topplaget, setter komponenten det tilbake. Se [Markup og oppførsel](/markup-og-oppforsel/).

## Attributter

| Attributt | Betydning | Standard |
| --- | --- | --- |
| `warn-at` | Sekunder uten aktivitet før varselet kommer | 1500 (25 minutter) |
| `expires-at` | Sekunder uten aktivitet før økten er ute | 1800 (30 minutter) |
| `activity-interval` | Sekunder mellom hver `session-activity` mens brukeren er aktiv | 60 |

Aktivitet er tastetrykk, klikk, berøring og rulling med mus, styreflate eller finger, også i en tabell eller et panel. Rulling som kode gjør, som en logg som følger med, teller ikke, ellers holdt siden økten i live mens brukeren var borte. Mens dialogen står åpen teller ikke aktivitet, ellers ville et tilfeldig museklikk forlenget økten uten at brukeren mente det.

Er `warn-at` eller `expires-at` ikke et tall større enn eller lik null, brukes standardverdien, og er `warn-at` ikke mindre enn `expires-at`, kommer varselet aldri. Komponenten sier fra om begge deler i konsollen.

Etter `session-expired` og `session-logout` står komponenten stille til `extend()` eller `reset()` kalles. Uten det fikk en app som ikke navigerte bort ny dialog og ny `session-expired` hvert `expires-at`-sekund, for en økt som alt var borte.

## Hendelser

| Hendelse | Når | Hva du gjør |
| --- | --- | --- |
| `session-warn` | Dialogen åpner seg | Som regel ingenting |
| `session-extend` | Brukeren velger å fortsette, med knappen eller Escape | Be serveren forlenge økten |
| `session-logout` | Brukeren velger å logge ut | Send brukeren til utloggingen |
| `session-expired` | Tiden er ute | Send brukeren til innloggingen |
| `session-activity` | Brukeren er aktiv, høyst én gang per `activity-interval` | Be serveren holde økten i live |

Komponenten vet ikke hvordan økten din forlenges. Den sier fra, du gjør kallet.

**Lytt på `session-activity` hvis serverøkten bare forlenges av kall til serveren.** Klokka her nullstilles av aktivitet i nettleseren. En bruker som skriver i et langt skjema uten et eneste kall, får derfor aldri varselet, mens serverøkten går ut, og innsendingen feiler. Hendelsen kommer i starten av et intervall og på slutten hvis brukeren har gjort noe siden, så serveren er aldri mer enn ett intervall bak.

**Flere faner deler ikke klokke.** Hver fane teller sin egen aktivitet, så en fane brukeren ikke bruker, viser varselet og sender `session-expired` mens brukeren arbeider i en annen. Skal fanene følge hverandre, la dem si fra til hverandre og kall `reset()`:

```js
const kanal = new BroadcastChannel("okt")
okt.addEventListener("session-activity", () => kanal.postMessage("aktiv"))
kanal.addEventListener("message", () => okt.reset())
```

## Metoder

| Metode | Hva den gjør |
| --- | --- |
| `extend()` | Nullstiller klokka, lukker varselet og sender `session-extend` |
| `reset()` | Nullstiller klokka og lukker varselet uten å sende noe. For en app som alt har forlenget økten selv, som når en autolagring gikk gjennom |

`extendSession(element)` og `resetSession(element)` fra `@fristil/designsystem/session-timeout` gjør det samme, men venter først på at elementet er registrert.

## Klasser du kan style

| Klasse | Hva det er |
| --- | --- |
| `.fs-session-timeout` | Vertselementet. Ligger som `display: contents` og tar ingen plass |
| `.fs-session-timeout__dialog` | Selve dialogen |
| `.fs-session-timeout__title` | Overskriften |
| `.fs-session-timeout__text` | Avsnittet med nedtellingen i |
| `.fs-session-timeout__count` | Tallet som teller ned |
| `.fs-session-timeout__actions` | Skjemaet med knappene |

Form og størrelse leses fra komponentvariabler, med systemets verdi som reserve:

| Variabel | Reserve |
| --- | --- |
| `--fs-session-timeout-width` | `26rem` |
| `--fs-session-timeout-padding` | `var(--fs-spacing-5)` |
| `--fs-session-timeout-radius` | `var(--fs-spacing-1)` |

```css
.fs-session-timeout__dialog {
  --fs-session-timeout-width: 32rem;
}
```
## Tilgjengelighet

Dialogen er en ekte `<dialog>` åpnet med `showModal()`, så fokusfellen, Escape og topplaget kommer fra nettleseren. Den har `role="alertdialog"`, fordi den avbryter noe brukeren ikke ba om å bli avbrutt i.

Tre ting er gjort med vilje, og alle tre er grunner til at dette er vanskelig å få riktig selv:

- **Fokus går tilbake dit brukeren var.** Uten det starter neste tastetrykk på toppen av siden, midt i et skjema.
- **Nedtellingen leses ikke opp hvert sekund.** Tallet på skjermen har `aria-hidden`, og opplesningen melder fra ved to minutter, ett minutt, 30 sekunder og 10 sekunder. En opplesning i sekundet gjør dialogen ubrukelig.
- **Opplesningen står på sidens språk.** Den er avsnittet ditt, med tallet byttet ut med en uttalt varighet. Varigheten skrives med nettleserens `Intl` etter `lang` på siden, så den sier «1 minutt og 30 sekunder» på en norsk side og «1 minute and 30 seconds» på en engelsk.

Sett knappen som forlenger først. Det er den de fleste vil ha, og den skal være det første tastaturet treffer.
